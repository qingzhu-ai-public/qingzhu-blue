# 蓝牙全景与协议栈

你戴着蓝牙耳机听歌，口袋里另一部手机正连着一台温度传感器。两者都叫蓝牙，走的却是两套不同的无线电和协议。这一篇把「蓝牙」这个词拆开，看清里面有几套东西、各管什么，后面所有章节的概念都能在这张地图上找到位置。

## 一个名字，两套无线电

蓝牙工作在 2.4 GHz 的 ISM 频段，和 Wi-Fi、微波炉共用这段频谱。同一个名字下面其实有两套传输方式。

| | 经典蓝牙 BR/EDR | 低功耗蓝牙 BLE |
|---|---|---|
| 出现时间 | 1999 年起的 1.x/2.x 规范 | 2010 年蓝牙 4.0 引入 |
| 信道划分 | 79 个信道，每个 1 MHz | 40 个信道，每个 2 MHz |
| 设计目标 | 持续的数据流，音频、串口 | 小数据、低频次，纽扣电池跑几个月到几年 |
| 典型设备 | 耳机、音箱、车机、存量串口设备 | 传感器、手环、标签、智能家居 |
| 应用接口 | Profile（A2DP、HFP、SPP 等） | GATT 服务与特征，或广播 |

两套无线电在物理层互不兼容，BLE 设备不能被只支持经典蓝牙的老手机发现。现在绝大多数手机是**双模**（Dual-mode），两套都支持；传感器往往只实现 BLE，称为单模。设备说明书上的「双模」指的就是这个。

BLE 的 40 个信道里，有 3 个专门用来发广播，编号 37、38、39，对应频率 2402、2426、2480 MHz。它们刻意避开了 Wi-Fi 最常用的 1、6、11 信道的中心频率。剩下 37 个数据信道在连接后使用，链路层用自适应跳频（AFH）在它们之间切换，躲开被 Wi-Fi 占用的频段。这就是为什么蓝牙和 Wi-Fi 挤在同一段频谱还能共存。

## 协议栈的分层

把两台设备竖着切开，蓝牙协议栈长这样。左边是 BLE 一侧，应用开发者主要和上半部分打交道。

```text
┌─────────────────────────────┐
│  应用（你的 App / 固件业务）      │
├─────────────────────────────┤
│  Host 主机                    │
│   GAP   设备发现与连接的角色流程  │
│   GATT  服务、特征、描述符       │
│   ATT   属性读写协议            │
│   SM    配对与密钥管理           │
│   L2CAP 通道复用与分段          │
├──────── HCI ────────────────┤
│  Controller 控制器             │
│   Link Layer  广播、扫描、连接时序│
│   PHY         1M / 2M / Coded  │
├─────────────────────────────┤
│  无线电（2.4 GHz）              │
└─────────────────────────────┘
```

分层不是学术装饰，它直接决定你排查问题时看哪份日志。

- **应用**调用系统 API。「读温度」「订阅通知」都发生在这一层。
- **主机**把业务意图翻译成协议操作。GATT 说「读这个特征」，ATT 把它变成一条带句柄的读请求，L2CAP 把这条请求装进通道。
- **HCI**（Host Controller Interface）是主机和控制器之间的标准接口。手机的应用处理器跑主机，蓝牙芯片跑控制器，两者通过 HCI 命令和事件通信。Android 的 HCI Snoop 日志记录的就是这一层的往来。
- **控制器**决定无线电什么时候开、在哪个信道发。广播间隔、连接事件、跳频都由链路层执行，应用干预不到这一层的时序。

经典蓝牙一侧的结构类似，但主机层换成了 LMP、SDP、RFCOMM 和各个 Profile。耳机走 A2DP 传音频、HFP 打电话，串口设备走 SPP。应用一般不直接操作这些协议，而是通过系统提供的 Profile 代理或 Socket。

## 规范文档怎么查

蓝牙规范由 Bluetooth SIG 维护，分几份文件，各管一摊。查资料时认名字比翻目录快。

- **Core Specification**：核心规范，无线电、链路层、HCI、ATT、GATT、GAP、SM 都在里面。本课程引用以 6.2 版为基线。
- **Core Specification Supplement（CSS）**：广播里各种 AD 数据类型的定义，比如 Flags、本地名称、厂商数据。
- **GATT Specification Supplement（GSS）**：标准特征的数据格式，比如温度怎么编码。
- **Assigned Numbers**：所有分配的编号，16 位 UUID、公司标识符、错误码都查这份。

这些都在 [bluetooth.com/specifications](https://www.bluetooth.com/specifications/specs/) 免费下载。遇到「这个字段到底几个字节」的问题，答案以规范为准，博客和教程包括本课程都只是导读。

## 一句话总结

**蓝牙是一个名字下的两套无线电，协议栈上半段管语义、下半段管时序，中间隔着 HCI；你的代码活在最上层，故障可能出在任何一层。**

## 面试题

1. 一台只支持 BLE 的传感器，能被只支持经典蓝牙的老手机发现吗？为什么？
2. BLE 的 3 个广播信道为什么选在 2402、2426、2480 MHz？
3. 应用调用「发起连接」后迟迟没有结果，想确认请求有没有到达蓝牙芯片，看哪一层的日志？
4. GATT 和 ATT 是什么关系？

### 参考答案

1. 不能。两套传输的物理层互不兼容，经典蓝牙设备扫描不到 BLE 广播。需要双模手机才能同时支持两者。
2. 这三个频率刻意避开了 Wi-Fi 1、6、11 信道的中心频率，减少广播被 Wi-Fi 干扰的概率。
3. HCI 日志。主机通过 HCI 向控制器下发命令，日志能确认命令是否发出、控制器回了什么事件。
4. GATT 定义数据的组织方式（服务、特征、描述符）和发现、读写、订阅流程；ATT 是实际访问属性表的协议操作。GATT 的流程靠 ATT 的操作完成。
