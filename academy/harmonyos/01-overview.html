鸿蒙 BLE 全景：ConnectivityKit 中心与外设

鸿蒙用 @ohos.bluetooth.ble（ConnectivityKit）做 BLE：中心扫描连接、外设 GattServer 广播，首批接口 API 10。这一课摆清模块地图、对象模型与三平台 API 对照，并给出最小可跑骨架。

第 1 步模块地图：access 管开关，ble 管收发

import { ble } from '@kit.ConnectivityKit';
ble.startBLEScan(filters, options)      // 扫描
ble.createGattClientDevice(deviceId)   // 中心客户端
ble.createGattServer()           // 外设服务端
模块职责首批版本
@ohos.bluetooth.access蓝牙开关、状态查询与订阅、设备地址持久化API 10
@ohos.bluetooth.bleBLE 扫描、广播、GATT 客户端/服务端API 10
@ohos.bluetooth.connection经典蓝牙连接、配对、本机名称API 10

NEXT 统一从 @kit.ConnectivityKit 导入（旧写法 import ble from '@ohos.bluetooth.ble' 仍可用）。所有蓝牙接口都要 ohos.permission.ACCESS_BLUETOOTH（D2 讲申请流程）。新增接口用上角标标版本，本课徽章均对照官方文档核实。

收束：中心 createGattClientDevice，外设 createGattServer；开关状态找 access。

第 2 步角色与三平台对照

手机默认中心+Client；鸿蒙也支持外设+Server（D7）。概念与 Android 一致：扫描→连接→发现→读写→订阅。

环节AndroidiOS鸿蒙
扫描BluetoothLeScanner.startScanscanForPeripheralsble.startBLEScan API 10
连接connectGattconnect(_:options:)GattClientDevice.connect API 10
发现discoverServicesdiscoverServicesgetServices（Promise）API 10
订阅setCharacteristicNotification + 写 CCCD 两步setNotifyValue 一步setCharacteristicChangeNotification 一步（系统自动写 CCCD）API 10
外设广播BluetoothLeAdvertiserCBPeripheralManager（仅名字+UUID）ble.startAdvertising（可带 serviceData）API 10
设备标识MACidentifier（本机 UUID）deviceId（虚拟 MAC，D3 细讲）
对照Android BluetoothLeScanner ≈ ble.startBLEScan；BluetoothGatt ≈ GattClientDevice。鸿蒙订阅像 iOS 一步完成，广播能力像 Android 能带服务数据——两边的好处都占了。
收束：概念三平台一致，API 名与细节不同；先认映射再写代码。

第 3 步最小骨架与串行规则

// 中心侧最小流程（权限与状态门控见 D2）
import { ble, access, constant } from '@kit.ConnectivityKit';

ble.on('BLEDeviceFind', (results: Array<ble.ScanResult>) => {
  // results[0].deviceId / rssi / data（原始广播 ArrayBuffer）
});
ble.startBLEScan([{ serviceUuid: '00001809-0000-1000-8000-00805f9b34fb' }]);

let client: ble.GattClientDevice = ble.createGattClientDevice(deviceId);
client.on('BLEConnectionStateChange', (state: ble.BLEConnectionChangeState) => {
  if (state.state === constant.ProfileConnectionState.STATE_CONNECTED) {
    client.getServices().then((services: Array<ble.GattService>) => {
      // 拿到 services 再读写/订阅
    });
  }
});
client.connect();
重点 · 串行规则鸿蒙 GATT 操作是串行的：读、写、订阅、MTU 协商，都要等上一步的异步回调返回再发下一步，否则报 2900011（operation busy）。官方文档在每个读写接口下都写了这条。把操作排成队列（Promise 链）是最稳的写法。
  • 事件先订阅再发起：on('BLEDeviceFind') 要在 startBLEScan 前；on('BLEConnectionStateChange') 要在 connect 前。
  • 单路扫描：startBLEScan 同时只能一路，重复开报 2902050；多路用 BleScanner（API 15+）。
  • close 释放：不用时 disconnect + close，避免句柄泄漏。
收束：事件先行、操作串行、用完 close；这三条贯穿后面所有课。
