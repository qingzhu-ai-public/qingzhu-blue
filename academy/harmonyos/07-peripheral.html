外设角色：GattServer 与广播

鸿蒙手机也能当外设：createGattServer 添加服务、startAdvertising 发广播、响应读写与发通知。关键优势：AdvertiseData 支持 serviceData——鸿蒙能当真正的 BTHome 广播源（iOS 做不到）。这一课讲外设全链路。

平台：HarmonyOS/ArkTS约 25 分钟API 10 → 22含两场交互演练跨端对照
1Server属性表+响应
2广播31字节预算
3BTHome服务数据源
4动手预算计算器
5自测六个问题

第 1 步GattServer：属性表 + 响应

let server = ble.createGattServer()
server.addService(service)
server.on('characteristicRead'/'characteristicWrite', respond)
API版本说明
createGattServer()API 10创建服务端对象
addService / removeService / removeAllServicesAPI 10管理属性表（服务/特征/描述符）
on('characteristicRead' / 'characteristicWrite')API 10中心来读写时触发，必须 sendResponse
sendResponse(serverResponse)API 10回数据/确认；不回中心会超时
notifyCharacteristicChanged(deviceId, notifyChar)API 10给已订阅的中心推通知/指示
getService / getServices / getConnectedStateAPI 22查属性表与连接状态
// 教学服务：READ+WRITE 特征 + CCCD 描述符（可被订阅）
let ch: ble.BLECharacteristic = {
  serviceUuid: '476cdf45-6063-43a1-b8e2-8c1fbed00601',
  characteristicUuid: '476cdf45-6063-43a1-b8e2-8c1fbed00602',
  characteristicValue: new Uint8Array([0x40,0x02,0xC4,0x09,0x03,0xBF,0x13]).buffer,
  descriptors: [{ descriptorUuid: '00002902-0000-1000-8000-00805f9b34fb',
                  descriptorValue: new Uint8Array([0x00,0x00]).buffer }],
  properties: { read: true, write: true, notify: true }
};
server.addService({ serviceUuid: ch.serviceUuid, isPrimary: true, characteristics: [ch] });

server.on('characteristicRead', (req: ble.CharacteristicReadRequest) => {
  server.sendResponse({ deviceId: req.deviceId, transId: req.transId,
    status: 0, offset: req.offset, value: ch.characteristicValue });
});
收束：Server 提供属性表+响应读写；收到请求必须 sendResponse。

第 2 步广播：31 字节预算

ble.startAdvertising(advSettings, advData)
server.notifyCharacteristicChanged(...)
API / 参数版本说明
startAdvertising(setting, advData, advResponse)API 10传统广播：advData + 扫描响应各 31 字节
startAdvertising(AdvertisingParams) + enable/disableAdvertising + on('advertisingStateChange')API 11新重载：带 duration，可开关与监听
AdvertiseSetting.intervalAPI 10[32, 16777215] slot×0.625ms，默认 1600（=1s）；传统广播上限 16384
AdvertiseSetting.txPowerAPI 10[-127, 1]，默认 -7（高 1 / 中 -7 / 低 -15）
AdvertiseSetting.connectableAPI 10默认 true；纯传感器广播可设 false
AdvertiseData.serviceDataAPI 10[{serviceUuid, serviceValue}]——BTHome 的关键
AdvertiseData.manufactureData / serviceUuidsAPI 10厂商数据 / UUID 列表
AdvertiseData.advertiseNameAPI 10需 ohos.permission.MANAGE_BLUETOOTH_ADVERTISER_NAME
重点外设发通知给已订阅的中心；双机实验一端 Server 一端 Client。广播是「无连接也到达」的通道，通知是「连接内」的通道，两者互补。
收束：广播按 AD 段拼预算；interval/txPower/connectable 三个旋钮。

第 3 步鸿蒙当 BTHome 广播源

ble.startAdvertising(
  { interval: 1600, txPower: -7, connectable: false },
  {
    serviceUuids: ['0000fcd2-0000-1000-8000-00805f9b34fb'],
    serviceData: [{
      serviceUuid: '0000fcd2-0000-1000-8000-00805f9b34fb',
      serviceValue: new Uint8Array([0x40,0x02,0xC4,0x09,0x03,0xBF,0x13]).buffer
    }]
  }
);
// 任何 BTHome 接收器（Android/iOS/鸿蒙/Home Assistant）都能收到 25.00°C / 50.55%
平台能发 BTHome 服务数据广播？原因
Android能AdvertiseData.setServiceData
鸿蒙能AdvertiseData.serviceData（API 10 起）
iOS不能startAdvertising 只支持 LocalName + ServiceUUIDs 两键
  • 双机实验：鸿蒙 A 机跑上面的广播源；鸿蒙 B 机（或 Android）按 D3 过滤 FCD2 收帧解码。iPhone 只能当接收器。
  • 定时更新：stopAdvertising → 改 serviceValue → startAdvertising；或用 API 11 重载的 enable/disableAdvertising。
  • connectable=false：纯广播传感器不需要连接，省电且避免中心误连。
收束：鸿蒙与 Android 一样能当 BTHome 源；这是 D9 实战「自发自收」的基础。
