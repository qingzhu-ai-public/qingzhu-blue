MTU、PHY 与连接参数：请求而非命令

requestMtu、PHY、requestConnectionPriority 都是「请求」，最终值由系统和两端协商。这一课讲怎么提请求、有效值怎么定、吞吐怎么估。

平台：Android/Kotlin约 12 分钟含交互演练前置：B5
1MTUrequestMtu
2PHY2M/Coded

第 1 步requestMtu 与有效值

gatt.requestMtu(247)   // 等 onMtuChanged(gatt, mtu, status)
// 有效 MTU = min(手机通告, 外设通告)
本步收束：requestMtu 是请求，onMtuChanged 给有效值（取小者）。

第 2 步2M 提速、Coded 换距离

gatt.setPreferredPhy(PHY_LE_2M_MASK, PHY_LE_2M_MASK, PHY_OPTION_NO_PREFERRED)
// 等 onPhyUpdate；需两端+系统支持（Android 8.0+ 才有接口）
PHY速率取舍
1M1 Mbit/s默认
2M2 Mbit/s更快更省发射时间
Coded500/125 kbit/s换距离
本步收束：PHY 要两端+系统三方支持；2M 提速、Coded 换距离。

第 3 步requestConnectionPriority

gatt.requestConnectionPriority(CONNECTION_PRIORITY_HIGH)  // 短 interval
// BALANCED / HIGH / LOW_POWER；最终值系统定
重点 · 吞吐估算应用吞吐 ≈ 每事件通知条数 × 每条值字节 ÷ interval。MTU247+DLE+2M+interval15ms 约几十 KB/s；只提 MTU 不开 DLE 仍被拆 27B 小包。规格书速率≠应用吞吐，实测。
本步收束：priority 是请求；吞吐要 MTU+DLE+PHY+interval 配合并实测。

动手调 MTU/PHY/优先级，估吞吐量级

外设 MTU 185、支持 2M。拖手机 requestMtu、选 PHY 与优先级（映射 interval），估应用吞吐量级。注意只提 MTU 不开 DLE 的空口效率问题（此处 DLE 默认开）。
