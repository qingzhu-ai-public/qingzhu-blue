线程、状态机与命令队列：每命令只结一次账

取消、断开、超时三个入口同时到，各自清理就会先「已取消」又「失败」。这一课把串行环境、状态机转移、代次隔离、四选一结一次、命令队列与背压逐一讲清，落到可复用的会话架构。

平台：Android/Kotlin约 24 分钟架构课含交互演练前置：B5

第 1 步所有入口只投递，不直接改状态

private val worker = Handler(HandlerThread("ble-session").apply{start()}.looper)
fun onUserCancel() { worker.post { handle(Event.Cancel) } }
fun onWriteTimeout(id:Long) { worker.post { handle(Event.Timeout(id)) } }
override fun onCharacteristicWrite(g,c,status) { worker.post { handle(Event.WriteDone(g,c.uuid,status)) } }

按钮（主线程）、定时器、Binder 回调三个入口都 post 进同一个串行队列，状态只在这一个线程里改。可选实现：HandlerThread、单线程 Executor、Kotlin 协程 newSingleThreadContext / Channel。核心是单一所有权。

本步收束：按钮/定时器/回调都 post 进同一队列，串行处理，状态单线程拥有。

第 2 步状态机：列出在哪步、允许去哪步

状态含义允许转移
CONNECTINGconnectGatt 已发→ DISCOVERING / CLOSING
DISCOVERINGdiscoverServices 已发→ CONFIGURING / CLOSING
CONFIGURING订阅/MTU/PHY 配置中→ READY / CLOSING
READY可收发命令→ CLOSING
CLOSING清理中→ CLOSED（只清理，不推进）

任一状态遇超时/断开/取消 → CLOSING → CLOSED。发 API 前记录「在等什么 + 期限」，进 CLOSING 后再来的事件只走清理。

本步收束：状态机列允许转移；关闭后只清理不推进。

第 3 步代次隔离 + 每命令完成恰好一次

重点 · 实现清单① 验代次：每次新建会话 gen+1，旧 GATT 迟到事件按 gen 丢弃；② CLOSING 只清理；③ WriteDone 匹配 GATT 实例 + 操作类型 + 特征 UUID 才算终态；④ 成功 / 同步拒绝 / 超时 / 取消 四选一完成一次；⑤ 完成取下一条，队列满返回忙。operationId 是 App 标识，平台回调没有，靠三要素匹配。
本步收束：代次隔离旧会话；每命令只结一次账（四选一）。

第 4 步命令队列与背压

  • 串行队列：一次只 inflight 一条，完成回调取下一条（呼应 B5 一次一操作）。
  • 背压：队列设上限，满了返回「忙」让上层退避，别无限堆积撑爆内存。
  • 优先级：关键命令（如停止）可插队，但要保证仍只结一次。
  • 多设备：每台一个会话/队列（任务池），互不阻塞——这正是 SDK 插件化任务池的思路。
本步收束：串行+背压+优先级；多设备各一会话，互不阻塞。
