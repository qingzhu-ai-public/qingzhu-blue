Android 蓝牙全景：两条路、协议栈与 API 地图

Android 上蓝牙有两条完全不同的路：经典蓝牙（BR/EDR）走 Profile/Socket，BLE 走 GATT。选错路后面代码全重来。这一课把两条路、协议栈分层、核心类与级别、GAP/GATT 角色摆清，作为整套 Android 课程的地图。

第 1 步经典蓝牙与 BLE 是两套接口

经典蓝牙 BR/EDRBLE（低功耗）
典型用途音频 A2DP/HFP、串口 SPP、键鼠 HID传感器、信标、价签、低功耗交互
应用接口RFCOMM Socket / 系统 Profile 代理GATT（服务 / 特征 / 描述符）
核心类BluetoothSocket / BluetoothServerSocket / BluetoothAdapterBluetoothLeScanner / BluetoothGatt / BluetoothGattServer
数据模型字节流（像串口）属性表（读 / 写 / 通知）
功耗较高低，纽扣电池可行
平台开放性Android 开放 SPP；iOS 普通 App 不开放（需 MFi）Android / iOS 都开放（iOS 用 CoreBluetooth）
选型铁律设备已定型时，按它实现的路来，并核对目标平台是否开放接口。双模设备（如手机）两条路都支持，但同一时刻不能既扫经典又扫 BLE。
本步收束：先确认设备走哪条路再选 API；经典字节流、BLE 属性表；iOS 拿不到 SPP。

3.2 经典蓝牙核心类

类 / 方法职责
BluetoothDevice.createRfcommSocketToServiceRecord(uuid)客户端按 SDP UUID 建 RFCOMM 连接

重点整条 BLE 链路是异步回调驱动：每一步发起后等对应回调，不能同步阻塞等结果。B9 会讲怎么把这些回调收进一个串行状态机。
本步收束：BLE 五类串异步链路（18/21 引入）；经典走 Socket/Profile；别阻塞等回调。

第 4 步GAP 四角色 × GATT 两角色

GAP 管「连接关系」，GATT 管「数据访问」，两套角色可交叉。手机默认是 Central + GATT Client。

GAP 角色做什么Android 支持
Broadcaster只发广播（不可连接）BluetoothLeAdvertiser（21）
Observer只扫描不连接BluetoothLeScanner（21）
Central扫描并发起连接connectGatt（18）
Peripheral发可连接广播、被连需 isMultipleAdvertisementSupported（21）
GATT 角色做什么对应类
Client读 / 写 / 订阅对端属性BluetoothGatt
Server暴露本地属性表、发通知BluetoothGattServer（18）
本步收束：GAP 管连接、GATT 管数据；手机默认 Central+Client；当 Peripheral 要查硬件能力。

第 5 步BluetoothAdapter 关键方法

方法作用备注
