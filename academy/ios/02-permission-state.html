权限与状态：poweredOn 才能扫描

iOS 要 Info.plist 声明蓝牙用途，运行时弹授权；CBCentralManager 初始化后等 centralManagerDidUpdateState 到 .poweredOn 才能扫描。这一课把两个 plist 键、六个状态、四个授权值逐一讲清，并演练「授权 × 开关」的全部组合。学完你能回答：弹窗什么时候出现、unauthorized 和 poweredOff 怎么区分处理、用户中途关蓝牙会发生什么。

第 1 步Info.plist 声明蓝牙用途：两个键分工

NSBluetoothAlwaysUsageDescription = "用于连接温度计读取温度"
// 旧系统另需 NSBluetoothPeripheralUsageDescription
键作用适用版本
NSBluetoothAlwaysUsageDescription「App 为什么要用蓝牙」的用途文案，显示在授权弹窗里iOS 13+
NSBluetoothPeripheralUsageDescription旧键：连接蓝牙外设的用途文案；iOS 13 起废弃iOS 6–12

官方规则（Apple 文档 Important 标注）：部署目标 ≥ iOS 13 只写 Always 键；部署目标 < iOS 13 两个键都要写——旧系统读旧键，新系统读新键。文案要具体（「连接你的温度计读取体温」），写「需要蓝牙」这种空话会被 App Store 审核打回。

<!-- Info.plist 片段 -->
<key>NSBluetoothAlwaysUsageDescription</key>
<string>用于连接你的温度计并读取温度</string>
<key>NSBluetoothPeripheralUsageDescription</key>  <!-- 仅当部署目标 < iOS 13 -->
<string>用于连接你的温度计并读取温度</string>
重点 · 崩溃不是异常是设计iOS 13+ 缺 Always 键时，App 一碰蓝牙 API 就被系统直接终止（TCC 隐私机制，日志里是 This app has crashed because it attempted to access privacy-sensitive data without a usage description）。这不是可以 try/catch 的错误，只能靠 plist 声明预防。
本步收束：不声明用途，初始化即崩溃/被拒；13+ 写 Always 键，要兼容旧系统就两个都写。

第 2 步六个状态逐一讲：等 .poweredOn 再扫描

func centralManagerDidUpdateState(_ c: CBCentralManager) {
  switch c.state {
  case .poweredOn: startScan()
  case .unauthorized: 提示去设置授权
  case .poweredOff: 提示打开蓝牙
  default: break }
}

state 的类型是 CBManagerState iOS 10 命名（旧名 CBCentralManagerState iOS 5–9 已废弃），六个值一个都不能漏：

状态值含义你该做什么
.unknown0刚初始化，状态还没确定等下一次回调，别干活
.resetting1蓝牙栈短暂重启，连接会丢等恢复回调，稍后重连
.unsupported2设备不支持 BLE（老模拟器等）提示设备不支持，别再重试
.unauthorized3用户拒绝了蓝牙授权引导去 设置→隐私→蓝牙 打开
.poweredOff4蓝牙开关关着（或飞行模式）提示打开蓝牙
.poweredOn5一切就绪可以扫描/连接
重点初始化 CBCentralManager 会触发授权弹窗；state 到 .poweredOn 之前不要扫描。用户可中途关蓝牙/撤授权，状态会再回调。连接中关蓝牙：所有连接断开（didDisconnectPeripheral 带 error），状态变 poweredOff——重连逻辑要等 poweredOn 回来再启动。
  • resetting 是短暂态：系统蓝牙服务重启（偶发），期间连接全部失效；正确姿势是等下一次 didUpdateState，不要立刻重试。
  • unsupported 常见于模拟器：iOS 模拟器不支持 BLE，真机调试是必修课。
  • 不要在 init 后立刻读 state 就下结论：第一拍几乎总是 .unknown，结论只能写在回调里。
本步收束：poweredOn 才扫描；unauthorized/poweredOff 分别提示；resetting 等恢复、unsupported 放弃。

第 3 步授权与状态分开看：CBManagerAuthorization

授权（用户允许 App 用蓝牙）与蓝牙开关（硬件 poweredOn）是两件事。CBManager.authorization 与 state 分别判断，界面分别提示。

授权值 iOS 13+含义界面动作
.notDetermined还没弹过窗（首次 init 会弹）等用户选择，别催
.restricted家长控制/MDM 限制，用户改不了提示受限制，别引导去设置
.denied用户点了「不允许」给「去设置」按钮（UIApplication.openSettingsURLString）
.allowedAlways已授权再看 state 决定能否扫描
// iOS 13+：用实例属性（类属性 CBManager.authorization 已在 13.1 废弃）
if #available(iOS 13.0, *) {
  switch central.authorization {
  case .denied:       showGoToSettings()
  case .restricted:   showRestrictedHint()
  case .notDetermined: break            // 弹窗在路上
  case .allowedAlways: break            // 看 state
  @unknown default:   break
  }
}
  • 弹窗时机：不是 init 那一行同步弹，而是系统准备好后弹；用户没选之前 state 停在 unknown/unauthorized 之间过渡，别在弹窗期间反复 init。
  • 拒绝不可逆（App 内）：denied 之后再 init 一万次也不会再弹窗，只能去系统设置改。
  • 设置里撤销授权：iOS 会直接终止 App（下次冷启动），不是只发个回调——别指望「撤销后热更新 UI」。
  • 授权 API 是 iOS 13+：更早系统没有蓝牙授权弹窗，state 直接反映开关；用 #available 分支。
本步收束：授权≠开关，分别判断提示；denied 引导去设置，restricted 别引导，撤销授权 App 会被终止。
