Why This Guide

为什么需要
《青竹蓝牙开发指南》

蓝牙资料并不少，但大多散落在官方 API、协议规范、厂商博客、零散 Demo 和线上事故复盘里。学习者缺的不是一篇文章，而是一条从协议到产品落地的完整路径

01

知识太散

协议栈、权限、扫描、GATT、配对、后台、抓包分散在不同资料里；看完仍拼不出完整链路。

02

经典蓝牙没人讲

多数教程只讲 BLE，RFCOMM、SPP、Profile Proxy、配对与绑定常常只留下几行 API。

03

BLE 只到 Demo

能连上、能写一条数据，不等于能处理地址轮换、假在线、串包、后台与机型差异。

04

学完还要造轮子

教程讲完就结束，正式项目还要自己写状态机、队列、重试、连接池和诊断。

05

教程和框架割裂

资料教一套概念，项目用另一套框架；学习成果无法直接变成产品能力。

《青竹蓝牙开发指南》把知识、实验和框架收在同一条路径里：教程讲清楚原理，SDK 把扫描、连接、队列、重试变成 SDK 的内部策略。先学会，再直接落地。

SDK｜startScan：扫描与过滤

就像给框架装一个统一入口——时长、信号、协议和身份都能筛选

SDK｜submit：任务式收发

就像把设备要做什么写成任务单——寻人、建连、队列、重试自动收口

自动寻人意图队列命令终态
06

SDK｜ProtocolPlugin：接自有协议

就像给同一台引擎换协议模块——公共能力不动，设备差异自己装

开发者用它做新设备接入：扫描识别、稳定身份、心跳和连接步骤都归插件
扫描识别稳定身份心跳 / 认证

Android BLE SDK

不只是教程，
还有能落地的内核

青竹 Android BLE SDK 把正式项目里最容易失控的部分收进 core：扫描、连接、队列、异常、调度和协议扩展。业务只表达「哪台设备要做什么」

先系统学

03

直接用 SDK

青竹 Android BLE SDK 提供任务式 API：扫描、自动寻人、队列、收发、重试、多设备调度和异常治理都已在内核里。

通过 ProtocolPlugin 描述广播识别、稳定身份、编解码、心跳和认证步骤，换设备不需要重写一套蓝牙栈。
