生命周期：退出页面取消订阅与断连

Flutter 页面退出要取消 Stream 订阅、断连释放，防泄漏与后台费电。这一课讲清理顺序、前后台切换与后台能力的边界。

第 1 步取消订阅：顺序与清单

@override void dispose() {
  scanSub?.cancel(); notifySub?.cancel();
  super.dispose();
}
// 完整清理清单：先退订、再断连、最后停扫
@override void dispose() {
  notifySub?.cancel();   // 1 退订 CCCD，不再收帧
  connSub?.cancel();     // 2 cancel 连接流 = 主动断开
  scanSub?.cancel();     // 3 停扫
  super.dispose();
}
// 重连场景同理：先 cancel 旧 connSub，再建新流（E4）
时机钩子动作
页面销毁State.dispose() Flutter三个订阅逐个 cancel
App 退后台WidgetsBindingObserver.didChangeAppLifecycleState Flutterpaused：停扫/按需断连；resumed：按状态门恢复
蓝牙被关statusStream ≠ ready（E2） 5.x清会话，等 ready 恢复
对端断开ConnectionStateUpdate.disconnected（E4） 5.x清订阅与队列，按策略重连
收束：dispose 取消所有订阅。

第 2 步断连与后台：能力边界

// 离开页面断开连接释放
// 后台持续传输需原生前台服务/桥接（E7）
  • iOS：App 退后台很快被挂起，Dart 代码停跑；CoreBluetooth 的后台模式与状态恢复是原生能力，跨端库不替你保活。
  • Android：后台扫描/连接受系统限制；持续传输要原生前台服务（foreground service）+ 通知，同样在原生侧。
  • 结论：reactive_ble 适合「前台交互」；后台持续采集 = 原生任务 + EventChannel 回传（E7），或干脆把采集放外设侧缓存。
// 前后台切换监听（WidgetsBindingObserver）
@override void didChangeAppLifecycleState(AppLifecycleState state) {
  if (state == AppLifecycleState.paused) {
    scanSub?.cancel();            // 后台别扫
  } else if (state == AppLifecycleState.resumed) {
    // 回前台：先查权限门×状态门（E2），再恢复扫描/重连
  }
}
重点跨端库后台能力有限，持续传输靠原生桥接。别指望 Dart 定时器在后台跑——iOS 挂起、Android 受调度。
收束：前台用库、后台靠原生；恢复前先过两道门。
