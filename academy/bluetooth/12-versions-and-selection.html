版本演进与选型：版本号不承诺能力

「蓝牙 5.0 比 4.2 快多少？」这问法本身就掉坑里。版本号标记按哪版规范认证，不承诺任何具体能力。这一课给你一张能力地图，再给一个照着走的选型判断顺序。

第 1 步一张演进表

版本关键能力对开发者意味着
4.0引入 BLE / GATT传感器起点，纽扣电池可能
4.2DLE / Secure Connections / 链路层隐私吞吐提升、ECDH 配对
5.02M/Coded PHY / 扩展广播速率翻倍或距离换速率
5.2LE Audio / EATT音频走向 BLE
6.0Channel Sounding 测距厘米级安全测距
6.2更短连接间隔（375µs）高性能 HID 延迟上限打开
本步收束：对日常开发影响最大的是 4.2 DLE、5.0 PHY、5.2 LE Audio。

第 2 步能力要设备、两端、系统三方点头

重点 · 核心认知标 5.0 的设备完全可以不实现 2M PHY。能力要设备实现 + 两端都支持 + 系统开放接口三方点头才算数。接新设备把版本号换成能力清单：支持哪些 PHY？MTU 多少？DLE？传统还是扩展广播？Legacy 还是 Secure Connections？

Bluetooth Mesh 不在这张表里，是 2017 单独的 Mesh Profile，面向几十上百节点组网；标 5.0 不代表支持 Mesh。

本步收束：版本号是认证标签，能力清单才是合同。

第 3 步经典 vs BLE，广播 vs 连接

先问设备实现了什么，再算数据量、频率、延迟三个数：

  • 小数据、低频、多接收方 → 广播（一对多无连接数限制、最省电）。
  • 双向交互、可靠传输、手机写配置 → BLE 连接 + GATT。
  • 音频 → 存量走经典 Profile（A2DP/HFP），新产品评估 LE Audio。
  • 存量 SPP 串口 → 经典蓝牙；注意 iOS 普通 App 拿不到 SPP（需 MFi）。
功耗直觉广播设备只在发包瞬间醒；连接设备每个事件都醒，interval 50ms = 每秒醒 20 次。纽扣电池跑一年要拉长间隔、用好 latency，或干脆走广播。吞吐别信规格书，实测。
本步收束：先看设备实现，再算三个数；小数据多听众走广播，双向走连接。

动手点版本看能力，再用三个数做选型

上半：点版本看它引入的能力（注意都是「可选」）。下半：选数据量、频率、接收方数量，给出广播/连接/经典的选型建议。
