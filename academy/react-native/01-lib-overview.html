RN 蓝牙全景：react-native-ble-plx

RN 用 react-native-ble-plx（BleManager）做 BLE，Promise/事件驱动。这一课讲选型、对象模型与逐 API 职责，对照原生。

第 1 步库选型

react-native-ble-plx 维护活跃、API 清晰；本板用它。BleManager 单例管理扫描/连接。

候选库API 风格维护方适合
react-native-ble-plx 3.5.1Promise + Device 对象 + 回调订阅dotintent（原 Polidea）本板：链式 async/await、对象化操作
react-native-ble-manager 12.6.1静态方法 + 全局事件（NativeAppEventEmitter）innoveit事件驱动风格；配套旧样例 thermometer-mvp 用它（F8 给映射）
自写原生模块自定义自己厂商 SDK/后台任务（F7）
  • 版本口径：npm 最新 3.5.1；官方文档站由 3.3 构建，核心 API 签名一致。本课徽章标 3.x。
  • 选型判据：plx 把设备做成对象（device.connect()/monitor…），错误走 BleError 枚举；manager 把一切做成全局事件。两种风格都成熟，本板统一 plx。
收束：BleManager 单例。

第 2 步对象模型与逐 API 讲解

const manager = new BleManager();
manager.startDeviceScan([uuid], null, (err, device)=>{})
await device.connect()
await device.discoverAllServicesAndCharacteristics()
API / 对象职责参数与结果来源版本 / 平台
new BleManager() / destroy()单例与销毁App 生命周期内一个实例；destroy 后不可再用3.x 双端
state() / onStateChange(cb, true)适配器状态State 六态；第二参 true 立即补发当前态（F2）3.x 双端
startDeviceScan(uuids, options, cb)扫描uuids=null 全收；cb(error, device)；stopDeviceScan 停3.x 双端
device.connect() / manager.connectToDevice(id)连接Promise<Device>；id 在 Android 是 MAC、iOS 是 UUID3.x 双端
discoverAllServicesAndCharacteristics()发现每连接一次必做一次（F4）3.x 双端
readCharacteristicForService(s, c)读Promise<Characteristic>，value 为 base643.x 双端
writeCharacteristicWithResponseForService(s, c, base64)带应答写WithoutResponse 版不等应答（F5）3.x 双端
monitorCharacteristicForService(s, c, cb)订阅返回 Subscription；cb(error, characteristic)3.x 双端
device.onDisconnected(cb)断开监听返回 Subscription；cb(error, device)3.x 双端
requestMTU(mtu)协商 MTUAndroid 有效；iOS 自动协商、调用无效果3.x Android 协商 / iOS 自动
对照原生回调 ≈ Promise + 事件订阅。Android 侧底层仍是 BluetoothGatt、iOS 侧 CoreBluetooth，plx 用原生模块把两端统一成同一套 JS API。
收束：对象化 API + base64 值 + Subscription 清理，是 plx 的三个心智锚点。
