综合实战：BTHome 温湿度计完整 App

这一课做一个真能跑的项目：一台手机当传感器（从端）广播 BTHome 温湿度，另一台手机当接收器（主端）扫描、解析、显示，还能把任意手机模拟成 Home Assistant。协议在哪、怎么对接、两端代码怎么写，全部讲一遍。

第 1 步BTHome 是什么、规范在哪

BTHome 是 Home Assistant 主推的开放 BLE 传感器广播标准。设备把读数按固定格式塞进广播包，接收端不用连接、不用配对，扫到就能解析。正因为是开放格式，Shelly、Xiaomi 一大批传感器、HA、ESPHome 都直接支持。

资源地址拿什么
官网bthome.io项目入口、设备列表
格式规范bthome.io/format广播结构、设备信息字节、全部对象 ID 表
加密规范bthome.io/encryptionAES-CCM 加密、nonce、防重放
源码github.com/home-assistant/bthome.io文档源，可追踪更新
参考解析器github.com/Bluetooth-Devices/bthome-blePython 解析器，含每种类型的测试样例
Kaitai 格式github.com/koenvervloesem/BTHome-Kaitai-Struct结构描述，可生成 11 种语言的解析代码
配套源码 · 可以直接编译本课的每一行代码都在 qingzhu-ble-android / samples / bthome-thermometer。一个 APK 两个角色，主端、从端、连接路线、单元测试全在里面。读课时开着它对照，比只看片段清楚得多。
对接协议的正确姿势不是找 SDK，而是读格式规范：确定 UUID → 确定设备信息字节 → 查对象 ID 表拿「类型 / 长度 / 有无符号 / 倍率」。这张表就是你写解析器需要的全部东西。
本步收束：规范在 bthome.io/format，对象 ID 表是解析的唯一天书。

第 2 步从广播包到 BTHome 数据：三层剥开

拿官方示例 020106 0B094449592D73656E736F72 0A16D2FC4002C40903BF13 剥三层。每个 AD 元素都是「长度 / 类型 / 数据」。

第 1 层 · AD 元素
02 01 06                  Flags: LE 可发现 + 不支持 BR/EDR（固定写 020106）
0B 09 4449592D73656E736F72  Complete Local Name = "DIY-sensor"
0A 16 D2FC4002C40903BF13    Service Data(16-bit UUID) ← BTHome 在这里

第 2 层 · 服务数据
D2FC                      UUID，按字节倒读 = 0xFCD2
40 02C409 03BF13          BTHome 数据

第 3 层 · BTHome 数据
40          设备信息字节 0100 0000
            bit0=0 不加密  bit2=0 定时广播  bit5-7=010 → v2
02 C409     对象 0x02 温度 sint16 LE 0x09C4=2500 ×0.01 = 25.00 °C
03 BF13     对象 0x03 湿度 uint16 LE 0x13BF=5055 ×0.01 = 50.55 %
重点 · 硬规则对象 ID 必须按数值从小到大排。接收端遇到不认识的 ID 就停止解析后面全部——排序是为了老接收端至少能读到前面认识的字段。v1 用的 UUID 是 0x181C / 0x181E，已废弃，新项目一律 v2 的 0xFCD2。
本课用到的对象ID类型倍率示例 → 结果
packet id0x00uint8100 2A → 42

湿度0x03uint16 LE0.0103 BF13 → 50.55 %
电压0x0Cuint16 LE0.0010C 020C → 3.074 V
电量0x01uint8101 5A → 90 %
本步收束：Flags + Name + Service Data(0xFCD2)；设备信息字节定版本；对象 ID 升序；小端 + 倍率 + 符号。

为什么要分 protocol 包解析是整个项目最容易出错的地方（字节序、符号、截断）。把它做成不依赖 Context 的纯函数，就能用官方测试样例当单元测试，不用两台手机也能验证解析器。
本步收束：协议层纯净可测；扫描、广播、UI 三块互不依赖。

第 4 步先写解析器，再用官方样例测

// protocol/BthomeObjects.kt
enum class Obj(val id: Int, val label: String, val len: Int, val signed: Boolean,
               val factor: Float, val unit: String, val min: Float, val max: Float) {
    PACKET_ID(0x00, "序号", 1, false, 1f,     "",   0f,    255f),
    BATTERY(0x01, "电量", 1, false, 1f,     "%",  0f,    100f),
    TEMPERATURE(0x02, "温度", 2, true,  0.01f,  "°C", -40f,  85f),
    HUMIDITY(0x03, "湿度", 2, false, 0.01f,  "%",  0f,    100f),
    VOLTAGE(0x0C, "电压", 2, false, 0.001f, "V",  0f,    65.535f);
}                               // min / max：越界只标红，不丢也不直接信
val OBJ_BY_ID = Obj.entries.associateBy { it.id }

// protocol/BthomeParser.kt
data class Measurement(val obj: Obj, val value: Float)
data class BthomeFrame(val version: Int, val encrypted: Boolean, val trigger: Boolean,
                       val measurements: List<Measurement>)

fun parse(serviceData: ByteArray): BthomeFrame? {
    if (serviceData.size < 2) return null
    val info = serviceData[0].toInt() and 0xFF
    val encrypted = info and 0x01 != 0
    val trigger   = info and 0x04 != 0
    val version   = (info shr 5) and 0x07
    if (version != 2) return null                 // 只处理 v2
    if (encrypted) return BthomeFrame(version, true, trigger, emptyList())  // 密文不解析

    val out = ArrayList<Measurement>()
    var i = 1
    var lastId = -1
    while (i < serviceData.size) {
        val id = serviceData[i].toInt() and 0xFF
        val o = OBJ_BY_ID[id] ?: break             // 规范：不认识就停
        if (id < lastId) break                     // 规范：必须升序
        if (i + 1 + o.len > serviceData.size) break // 截断包，不能越界读
        val raw = readLE(serviceData, i + 1, o.len, o.signed)
        out += Measurement(o, raw * o.factor)
        lastId = id
        i += 1 + o.len
    }
    if (out.isEmpty()) return null                 // 一个对象都没解出来 → 无效帧
    return BthomeFrame(version, false, trigger, out)
}

private fun readLE(b: ByteArray, off: Int, len: Int, signed: Boolean): Int {
    var v = 0
    for (k in 0 until len) v = v or ((b[off + k].toInt() and 0xFF) shl (8 * k))
    if (signed) when (len) {                      // 符号扩展
        1 -> v = v.toByte().toInt()
        2 -> v = v.toShort().toInt()
    }
    return v
}
重点 · 四个坑一次堵死① 每个字节先 and 0xFF，否则 Kotlin 的 Byte 有符号，0xC4 会变成 -60；② 小端要符号扩展，零下温度才对；③ 不认识的 ID 立即停，不抛异常也不硬解；④ 边界检查防截断包崩溃。

第 5 步扫描：只收 0xFCD2，按地址合并

// scanner/BthomeScanner.kt
private val BTHOME_UUID: ParcelUuid =
    ParcelUuid.fromString("0000FCD2-0000-1000-8000-00805F9B34FB")

@RequiresPermission(BLUETOOTH_SCAN)
fun start() {
    val filter = ScanFilter.Builder()
        .setServiceUuid(BTHOME_UUID)              // 控制器层过滤，省电
        .build()
    val settings = ScanSettings.Builder()
        .setScanMode(ScanSettings.SCAN_MODE_LOW_LATENCY)
        .build()
    scanner.startScan(listOf(filter), settings, callback)
}

private val callback = object : ScanCallback() {
    override fun onScanResult(type: Int, r: ScanResult) { emit(r) }
    override fun onScanFailed(code: Int) {        // 必须处理，否则界面一直转圈
        running = false
        _errorCode.value = code                   // 1=已在跑 2=注册失败 5=资源不足 6=太频繁
        _error.value = describe(code)             // 界面按码决定：退避重试，还是停下报错
    }
}

private fun emit(r: ScanResult) {
    val bytes = r.scanRecord?.getServiceData(BTHOME_UUID) ?: return
    val frame = parse(bytes) ?: return             // 版本不对/加密 → 忽略
    if (frame.encrypted) return                    // 本课不处理加密
    _readings.tryEmit(SensorReading(
        address = r.device.address, rssi = r.rssi,
        name = r.scanRecord?.deviceName ?: r.device.name,
        measurements = frame.measurements.associate { it.obj to it.value }
    ))
}
重点 · setServiceUuid 的两个好处过滤在蓝牙控制器里做，App 不会被无关广播唤醒；同时 Android 会替你把 Service Data 重组好，getServiceData() 直接返回 D2FC 之后的字节，不用自己剥 AD 结构。

同一个地址每秒来好几条广播，UI 只需要「每台设备最新一条」。用地址做 key 合并：

// scanner/BthomeRepository.kt
val readings: Flow<List<SensorReading>> = callbackFlow {
    val latest = ConcurrentHashMap<String, SensorReading>()
    scanner.readings.onEach { latest[it.address] = it; trySend(snapshot(latest)) }
        .launchIn(this)
    // 没有新广播也要每秒刷一次，才能把 10s 没更新的设备标成离线
    flow { while (true) { emit(Unit); delay(1_000) } }
        .onEach { trySend(snapshot(latest)) }.launchIn(this)
    scanner.start()
    awaitClose { scanner.stop() }                  // 取消收集 = 停扫描
}.flowOn(Dispatchers.Default)

fun snapshot(latest): List<SensorReading> = latest.values
    .map { it.copy(online = now - it.timestamp < OFFLINE_AFTER_MS) }   // 10_000
    .sortedByDescending { it.timestamp }
本步收束：ScanFilter 按 UUID 过滤；onScanFailed 必处理；按地址保留最新值。

第 6 步让手机变成 BTHome 传感器

从端就是反过来：把读数编码成字节，塞进 AdvertiseData.addServiceData()。Android 8.0+ 用 startAdvertisingSet，能中途改数据而不用停广播。

// protocol/BthomeEncoder.kt
fun encode(ms: List<Measurement>): ByteArray {
    val sorted = ms.sortedBy { it.obj.id }          // 必须升序
    val out = ByteArrayOutputStream()
    out.write(0x40)                                  // v2, 不加密, 定时
    for (m in sorted) {
        out.write(m.obj.id)
        val raw = Math.round(m.value / m.obj.factor)
        repeat(m.obj.len) { k -> out.write((raw shr (8 * k)) and 0xFF) }
    }
    return out.toByteArray()
}

// advertiser/BthomeAdvertiser.kt
@RequiresPermission(allOf = [BLUETOOTH_ADVERTISE, BLUETOOTH_CONNECT])
fun start(connectable: Boolean, listener: BthomeGattServer.Listener?): Boolean {
    val advertiser: BluetoothLeAdvertiser =
        adapter.bluetoothLeAdvertiser ?: return notSupported()
    val params = AdvertisingSetParameters.Builder()
        .setConnectable(connectable)               // 纯广播不可连；开了连接路线才可连
        .setScannable(true)                        // 要发扫描响应（放设备名），必须可扫描
        .setLegacyMode(true)                       // 兼容 4.x 接收端
        .setInterval(AdvertisingSetParameters.INTERVAL_LOW)   // ≈100ms
        .setTxPowerLevel(AdvertisingSetParameters.TX_POWER_MEDIUM)
        .build()
    val data = buildData() ?: return false         // 超 31 字节就不发，原因写进 status
    advertiser.startAdvertisingSet(params, data, buildScanResponse(), null, null, cb)
    return true
}

private fun buildData() = AdvertiseData.Builder()
    .addServiceData(BTHOME_UUID, encode(current))  // 主包：Flags 3 + 服务数据
    .build()
private fun buildScanResponse() = AdvertiseData.Builder()
    .setIncludeDeviceName(true)                    // 设备名放扫描响应，各有 31 字节
    .build()

// 数值变了就热更新，不用停广播。异步的：上一次没回调前再设会被丢，用 dirty 合并
private fun push(ms: List<Measurement>) {
    current = ms
    if (updating) dirty = true else { updating = true; set?.setAdvertisingData(buildData()) }
}
重点 · 31 字节预算Legacy 广播主包只有 31 字节：Flags 3 + Service Data（长度 1 + 类型 1 + UUID 2 + 数据 7）= 14，名字再往里塞就紧张了。名字太长会被系统拒绝（ADVERTISE_FAILED_DATA_TOO_LARGE）。所以源码把名字挪到扫描响应——它另有一份 31 字节预算，两边互不挤占。要更长就开扩展广播。
本步收束：encode 升序写小端；setConnectable(false)；INTERVAL_LOW；setAdvertisingData 热更新。

第 8 步连接和发数据：广播没有的，自己补一条练手路线

先把边界说清楚：BTHome 没有连接。规范首页写着它的目标是「用 BLE 发现包共享传感器数据和按键」，不提供控制通道。广播路线里的「发数据」就是从端改广播，主端扫到即得，全程不连接、不配对——这正是它省电的原因。规范里的 Events（0x3A 按钮事件）和 Commands（0x3B）也都是广播里的对象，不是 GATT。

那「连接、发数据」怎么练？源码里多了一条明确标注的教学扩展路线（不属于 BTHome 标准）：从端多开一个自定义 GATT 服务，主端连上来订阅，从端每来一帧新读数就推一帧；主端也能写一帧回去改从端的读数。帧格式不变，所以两端共用同一个 parse() / encode()。流程就是 B4、B5、B6 讲的那条线。

服务9d1f0001-5c6b-4e7a-9b0c-1d2e3f4a5b6c128 位随机 UUID，不冒用任何已登记的 16 位 UUID
特征9d1f0002-5c6b-4e7a-9b0c-1d2e3f4a5b6cNOTIFY + WRITE

val ch = BluetoothGattCharacteristic(CHAR_UUID,
    PROPERTY_NOTIFY or PROPERTY_WRITE or PROPERTY_WRITE_NO_RESPONSE, PERMISSION_WRITE)
ch.addDescriptor(BluetoothGattDescriptor(CCCD_UUID, PERMISSION_WRITE))

override fun onDescriptorWriteRequest(device, requestId, descriptor, preparedWrite,
                                      responseNeeded, offset, value) {
    if (descriptor.uuid != CCCD_UUID) return
    if (responseNeeded) server.sendResponse(device, requestId, GATT_SUCCESS, 0, byteArrayOf())
    subscribed = value.contentEquals(ENABLE_NOTIFICATION_VALUE)   // 收到 0x0001 = 订阅
    if (subscribed) notify(encode(current))                        // 订阅完立刻给一帧
}

override fun onCharacteristicWriteRequest(device, requestId, ch, preparedWrite,
                                          responseNeeded, offset, value) {
    if (responseNeeded) server.sendResponse(device, requestId, GATT_SUCCESS, 0, byteArrayOf())
    parse(value)?.let { listener.onCommand(it.measurements) }      // 和广播同一套解析
}

// ── 主端 scanner/BthomeGattClient.kt：一步步来 ──
gatt = device.connectGatt(ctx, false, callback, TRANSPORT_LE)

override fun onConnectionStateChange(g, status, newState) {
    if (newState == STATE_CONNECTED) g.discoverServices()          // ① 连上 → 发现服务
}
override fun onServicesDiscovered(g, status) {
    val ch = g.getService(SERVICE_UUID).getCharacteristic(CHAR_UUID)
    g.setCharacteristicNotification(ch, true)                      // ② 先让本机栈收
    g.writeDescriptor(ch.getDescriptor(CCCD_UUID), ENABLE_NOTIFICATION_VALUE)  // ③ 再告诉设备
}
override fun onCharacteristicChanged(g, ch, value: ByteArray) {    // ④ Android 13+ 是三参数
    show(parse(value))                                            //    和广播同一套解析
}
// ⑤ 写：把从端温度设为 30.00 °C
gatt.writeCharacteristic(ch, encode(listOf(Measurement(TEMPERATURE, 30f))), WRITE_TYPE_DEFAULT)
重点 · 三个坑① setCharacteristicNotification(true) 只让本机蓝牙栈接收，设备并不知道；必须再往设备的 CCCD 写 0x0001，它才会发通知。② 顺序不能反。③ Android 13 起回调多了 value 参数，写入和写描述符改成返回 int 状态码；旧接口标了废弃但仍可用，源码按版本分支。另外：可连接广播被连上后会停，断开后系统自动恢复——被连上期间别的接收端扫不到它是正常的。

实际跑起来是这样：从端勾「允许主端连接」并广播 → 主端点列表里这台设备 → 连接面板滚动显示通知帧 → 点「写入：把从端温度设为 30.00 °C」→ 从端解析后切到手动数据源、温度变 30 → 广播同步更新。

本步收束：BTHome 本身不连接；要练连接就用同一套帧走 GATT：connectGatt → discoverServices → CCCD 0x0001 → notify / write。

第 10 步做完之后往哪走

方向做什么关键点
加密bit0=1，AES-CCM，密钥 16 字节nonce = MAC(6) + UUID(2) + 设备信息(1) + counter(4)；末尾是 4 字节 counter + 4 字节 MIC；接收端必须校验 counter 递增防重放
真传感器ESP32-C3 + SHT4x，ESPHome 发 BTHome放电量对象 0x01，电池设备把间隔拉到 1s 以上
接 HAHA 装 Bluetooth 集成即自动发现你的设备名会成为 HA 里的实体名
需要双向广播不够用，回到 GATT 连接路线BTHome 不定义 GATT；本课的连接路线是自定义教学服务，正式产品按 B4–B9 自己定服务、特征和指令
后台常驻从端放前台服务回到 B10：connectedDevice 类型 + 通知
本步收束：广播路线适合单向遥测；要配置、要历史、要可靠送达就走连接。
