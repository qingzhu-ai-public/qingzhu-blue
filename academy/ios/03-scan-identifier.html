扫描与过滤：服务 UUID 与 identifier 去重

scanForPeripherals(withServices:) 用广播里的服务 UUID 缩小范围；peripheral.identifier 是系统给的 UUID，用它合并同一行。这一课把扫描 API 族、广播字典的每个键、identifier 与 MAC 的本质区别、取回旧设备的两条路逐一讲清。学完你能回答：为什么加了过滤设备消失、为什么换台 iPhone identifier 就变了、不扫描怎么拿回上次连过的设备。

第 1 步扫描 API 族与 withServices 过滤

central.scanForPeripherals(withServices: [CBUUID(string:"1809")], options: nil)
API作用引入
scanForPeripherals(withServices:options:)开扫；services 传 nil 全收（前台才行），传数组按广播声明过滤iOS 5
stopScan()停扫；找到目标就停，永远限时iOS 5
isScanning当前是否在扫（别重复 start）iOS 9
centralManager(_:didDiscover:advertisementData:rssi:)结果回调：设备对象 + 广播字典 + 信号iOS 5

1.1 advertisementData 字典里有什么

键值引入
CBAdvertisementDataLocalNameKey广播里的设备名（可能没有；连接后 peripheral.name 更可靠）iOS 5
CBAdvertisementDataServiceUUIDsKey广播声明的服务 UUID 数组（withServices 筛的就是它）iOS 5
CBAdvertisementDataManufacturerDataKey厂商数据 Data（前 2 字节厂商 ID，如 Apple 0x004C）iOS 5
CBAdvertisementDataServiceDataKey[CBUUID: Data] 服务数据（如 BTHome 0xFCD2）iOS 5
CBAdvertisementDataTxPowerLevelKey发射功率 NSNumber（测距辅助）iOS 5
CBAdvertisementDataIsConnectable是否可连接 NSNumberiOS 7
重点筛的是广播中声明的服务。设备支持某服务不代表每次广播都公布它；列表空先确认外设有广播该 UUID。后台扫描必须带服务 UUID。与 Android 的 ScanFilter 相比，iOS 只开放「服务 UUID」这一种系统级过滤，按名字/厂商数据筛要自己在 didDiscover 里做。
本步收束：withServices 筛广播声明；后台必须带 UUID；其余过滤自己在回调里做。

第 2 步identifier 合并同一行，不是 MAC

peripheral.identifier 是 CoreBluetooth 给的 UUID，用于本机记录/查找，不是 MAC。名字可重复、地址会轮换；跨手机识别用设备序列号等稳定业务标识。

标识谁生成跨 App跨手机能不能拿到
MAC 地址外设厂商/随机轮换——iOS 拿不到（隐私设计，Android 能拿）
peripheral.identifier本机系统按设备生成同一台手机上稳定不同！每台手机各给一个UUID 属性直接读
产品 stableId（序列号等）产品固件写进广播/特征稳定稳定自己解析广播或读特征
  • 本机长期关联：存 identifier，下次用 retrievePeripherals(withIdentifiers:) 直接取回（见第 4 步），不用重扫。
  • 跨手机/云端绑定：identifier 换台手机就变，必须用产品自己的 stableId（序列号、出厂 ID）做主键。
  • identifier 也可能变：手机还原网络设置、外设配对信息被清除等场景可能重新分配——取回后连不上要回退到扫描。
  • 去重列表：UI 列表按 identifier 合并行；名字会重名，RSSI 会波动，都不可靠。
本步收束：identifier 本机去重；跨手机用 stableId；iOS 永远拿不到 MAC。

第 3 步默认合并，AllowDuplicates 才多次回调

默认系统合并重复发现。要观察广播值/RSSI 多次更新，前台用 CBCentralManagerScanOptionAllowDuplicatesKey:true，仍按 identifier 合并列表，结束及时停扫。RSSI 只配观察不配身份。

central.scanForPeripherals(withServices: [CBUUID(string: "1809")],
  options: [CBCentralManagerScanOptionAllowDuplicatesKey: true])  // iOS 5+
场景AllowDuplicates=false（默认）AllowDuplicates=true
前台扫描每台设备只回调一次（系统合并）每收到一包就回调，RSSI/广播值持续刷新
后台扫描合并被忽略，仍合并（官方文档明确）
典型用途找设备列表、连接测距、观察 BTHome 广播传感器、找最强信号
重点 · 省电AllowDuplicates 会显著增加回调频率与耗电，只在需要连续观察时开，且用完就 stopScan。持续扫描广播传感器（如温度计广播模式）是它的正当用途；找设备连接则不需要。
本步收束：默认去重；AllowDuplicates 前台多次回调、后台被忽略；用完就停。

第 4 步不扫描取回设备：retrieve 两条路

扫描不是拿 CBPeripheral 的唯一途径。系统记得「见过/连过」的设备，两条 retrieve API 可以直接取回对象，比重新扫描快得多：

API取回什么引入
retrievePeripherals(withIdentifiers: [UUID])本机系统认识的设备（扫到过/连过/配对过），按你存的 identifier 取iOS 7
retrieveConnectedPeripherals(withServices: [CBUUID])当前已连到系统的设备（包括被其他 App 或系统服务连着的），按服务筛iOS 7
// 路线一：上次连过，存了 identifier
let known = central.retrievePeripherals(withIdentifiers: [savedUUID])
if let p = known.first {
  p.delegate = self
  central.connect(p, options: nil)   // 取回 ≠ 已连接，仍要 connect
}

// 路线二：设备可能已被别的 App 连到系统（如手环被健康 App 连着）
let connected = central.retrieveConnectedPeripherals(withServices: [CBUUID(string: "1809")])
// 返回的 peripheral 可能 state 已是 .connected，直接 discoverServices 即可
  • 取回的对象要检查 state：retrieveConnectedPeripherals 拿到的可能已经 .connected，跳过 connect 直接发现服务；retrievePeripherals 拿到的通常 .disconnected，要走 connect。
  • 连不上要回退：identifier 失效（换机/重置）时 retrieve 返回空数组或 connect 无响应，回退到扫描流程。
  • connect 无超时：对不在场的设备 connect 会一直挂着（这是特性，见 C4），配合超时定时器自己管理。
本步收束：存 identifier 用 retrievePeripherals 秒回；查系统级连接用 retrieveConnectedPeripherals；取回后按 state 决定 connect 与否。
