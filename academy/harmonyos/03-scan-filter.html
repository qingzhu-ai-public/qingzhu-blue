扫描与过滤：startBLEScan 与 BLEDeviceFind

startBLEScan(filters,options) 后 on('BLEDeviceFind') 收结果。这一课讲清 ScanResult 每个字段的版本（serviceDataMap 要 API 22+）、虚拟 MAC 的坑、过滤字段与旧版本手解 AD 结构的兜底。

平台：HarmonyOS/ArkTS约 25 分钟API 10 → 23含两场交互演练跨端对照

2结果字段版本

第 1 步扫描回调与结果字段

ble.on('BLEDeviceFind', (devices)=>{ /* deviceId, rssi, data */ })
ble.startBLEScan([{ serviceUuid: '00001809-…' }], { interval:0 })
ScanResult 字段版本说明
deviceIdAPI 10设备地址（默认虚拟 MAC，见第 3 步）
rssiAPI 10信号强度 dBm，只配排序
dataAPI 10原始广播 ArrayBuffer（AD 结构），永远可用
deviceName / connectableAPI 10广播名（0x09）/ 可连接标志
serviceUuids / manufacturerDataMap / serviceDataMap / advertiseFlagsAPI 22系统解析好的结构化字段
addressAPI 23真实 MAC（配合过滤条件）
重点 · 版本兜底要读 BTHome 服务数据，API 22+ 直接用 serviceDataMap；API 10–21 只有原始 data，要自己按 AD 结构（长度/类型/值）解析出 0x16 服务数据段。D9 实战的解码器两条路都实现了。
  • 单路扫描：startBLEScan 全局一路，重复开报 2902050；换过滤要先 stopBLEScan。
  • 多路扫描：BleScanner（API 15）可多实例并行；过滤器硬件资源全局共享，单应用建议 ≤3 个，占满报 2900009。
  • filters=null 全扫：能跑但不建议——费电、结果杂，生产环境总是带过滤。
收束：on BLEDeviceFind 收结果；data 永远在，结构化字段看版本。

第 2 步旧版本兜底：手解 AD 结构

// 手解 AD 结构（API 10–21 兜底；ArkTS）
function extractServiceData(raw: ArrayBuffer, uuid16: number): Uint8Array | null {
  let bytes = new Uint8Array(raw);
  let i = 0;
  while (i < bytes.length) {
    let len = bytes[i];
    if (len === 0) break;
    let type = bytes[i + 1];
    if (type === 0x16 && len >= 3) {
      let u = bytes[i + 2] | (bytes[i + 3] << 8); // 小端 UUID
      if (u === uuid16) return bytes.slice(i + 4, i + 1 + len);
    }
    i += len + 1;
  }
  return null;
}
收束：AD 三段式循环切；0x16 段头两字节是小端 UUID，剩下是载荷。

第 3 步过滤、虚拟 MAC 与扫描参数

filters 筛广播声明的服务；deviceId 去重。筛不到先去掉过滤看原始 data。RSSI 只配排序。

ScanFilter 字段版本匹配对象
serviceUuid + serviceUuidMaskAPI 10广播里的服务 UUID 列表（BTHome 用 FCD2）
nameAPI 10广播名（0x09/0x08）
serviceData + serviceDataMaskAPI 10服务数据段（ArrayBuffer 前缀匹配）
manufactureId / manufactureData(+Mask)API 10厂商数据（0xFF）
deviceIdAPI 10地址（虚拟 MAC 语义）
addressAPI 23真实 MAC
重点 · 虚拟 MAC鸿蒙隐私保护：扫描结果的 deviceId 默认是虚拟 MAC——蓝牙开关重启后立即变化；配对后保持稳定。所以别把 deviceId 当持久标识存库；跨会话认设备用广播里的稳定字段（名字/服务数据/序列号），或用 access 的持久化设备地址能力。
ScanOptions版本说明
intervalAPI 10批量上报延迟 ms，默认 0（立即上报）
dutyModeAPI 10默认 SCAN_MODE_LOW_POWER（省电）
matchModeAPI 10默认 MATCH_MODE_AGGRESSIVE（弱信号也报）
phyTypeAPI 12默认 PHY_LE_1M； coded PHY 用于远距
reportModeAPI 15普通/围栏/批量上报
重点过滤字段必须真实在广播里，同 A2/B3：BTHome 传感器广播里没有名字时，name 过滤永远筛不到。
收束：过滤对准广播真实字段；deviceId 去重可以、持久化不行。
