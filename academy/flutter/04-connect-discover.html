连接与发现：connectToDevice 流与 discoverServices

connectToDevice(id:) 返回连接状态 Stream；discoverServices 拿服务特征。这一课讲连接状态机、发现时机与重连纪律。

第 1 步连接流

ble.connectToDevice(id: deviceId, servicesWithCharacteristicsToDiscover:{...})
  .listen((s){ /* ConnectionState.connected */ })
ConnectionState含义该做什么
connecting正在建立连接UI 转圈，别发 GATT 操作
connected连接建立发起 discoverServices
disconnecting正在断开准备清理
disconnected已断开（含对端关机/超距）清会话；按策略重连
  • ConnectionStateUpdate 除 connectionState 外还带 deviceId 与 error：断开原因（如对端终止）从 error 读，别只看守状态。
  • connectionTimeout 可选：超时后流发 disconnected；不设置则依赖系统超时。
  • connectToAdvertisingDevice：先按 withServices 预扫（prescanDuration）再连，适合「设备还没进扫描列表」的场景。
  • cancel 连接流 = 主动断开：这是 reactive_ble 的语义，重连前先 cancel 旧流。
收束：连接状态走 Stream。

第 2 步发现与重连纪律

await ble.discoverServices(deviceId)
// 三个发现相关 API 的分工
final services = await ble.discoverServices(deviceId);
// → List<DiscoveredService>，含特征与描述符
await ble.discoverAllServices(deviceId);   // 只发现不返回，存库内
final cached = await ble.getDiscoveredServices(deviceId);

// 部分发现加速：连接时只发现关心的服务/特征
ble.connectToDevice(
  id: deviceId,
  servicesWithCharacteristicsToDiscover: {
    svcUuid: [chrUuid],
  },
).listen((u) {
  if (u.connectionState == ConnectionState.connected) {
    // 可以读写订阅了
  }
});
API返回版本 / 平台
connectToDevice / connectToAdvertisingDeviceStream<ConnectionStateUpdate>5.x 双端
discoverServicesFuture<List<DiscoveredService>>5.x 双端
discoverAllServices / getDiscoveredServicesFuture<void> / Future<List<Service>>5.x 双端
connectionTimeout / servicesWithCharacteristicsToDiscover连接可选参数5.x 双端
重点connected 才发现；重连重新发现/订阅。断开后旧特征对象全部失效；重连流程 = cancel 旧流 → 新 connectToDevice → 重新发现 → 重新 subscribe。
收束：发现是「每连接一次」的动作，不是一次性缓存。
