CoreBluetooth 全景：中心与外设的 API 地图

iOS 用 CoreBluetooth 框架做 BLE：CBCentralManager 当中心扫描连接，CBPeripheralManager 当外设发广播。这一课把对象模型、两个 delegate 的每个回调、各类的引入版本逐一讲清，并给出一份能跑的最小骨架。学完你能回答：结果为什么只能靠回调拿、iOS 和 Android 的 API 形态差在哪、每个类从哪个 iOS 版本开始可用。

第 1 步Manager → Peripheral → Service → Characteristic

先把对象地图铺开。中心角色只有两个「主动对象」：CBCentralManager 负责扫描与连接，扫到的每台设备是一个 CBPeripheral；连上之后，设备内部的属性表以 CBService → CBCharacteristic → CBDescriptor 三层对象树暴露给你。所有 UUID 都用 CBUUID 包装。

CBCentralManager      扫描/连接（中心）
   ↓ didDiscover → CBPeripheral
CBPeripheral          discoverServices / readValue / setNotifyValue
   ↓ CBService → CBCharacteristic → CBDescriptor
CBPeripheralManager   当外设发广播/提供属性表

1.1 核心类与引入版本（对照 Apple 文档核实）

类职责引入
CBCentralManager中心：扫描、连接、取回已知设备、连接事件监听iOS 5
CBPeripheral一台远端设备：发现服务/特征、读写、订阅、RSSI、L2CAPiOS 5
CBService / CBCharacteristic / CBDescriptor属性树三层：服务 → 特征 → 描述符iOS 5
CBUUIDUUID 包装：16 位短号自动展开成 128 位iOS 5
CBPeripheralManager外设：发广播、提供属性表、响应读写iOS 6
CBMutableService / CBMutableCharacteristic外设自建属性表用的可变类iOS 6
CBManager两个 Manager 的公共基类：state / authorizationiOS 10
CBL2CAPChannel面向流的高吞吐通道，绕开 GATT 逐包读写iOS 11
本步收束：中心用 CBCentralManager+CBPeripheral；外设想用 CBPeripheralManager。属性树三层，UUID 一律 CBUUID。

第 2 步一切靠 delegate 回调：两个协议逐条认

所有操作异步，结果走 CBCentralManagerDelegate / CBPeripheralDelegate：didDiscover、didConnect、didDiscoverServices、didUpdateValueFor… 不能同步等结果。调用 API 只是「发起请求」，成败与数据都在稍后的回调里。

2.1 CBCentralManagerDelegate：扫描与连接事件

回调何时触发引入
centralManagerDidUpdateState(_:)蓝牙状态变化（唯一必须实现的方法），poweredOn 后才能干活iOS 5
centralManager(_:didDiscover:advertisementData:rssi:)扫到一台匹配设备，带广播字典与信号强度iOS 5
centralManager(_:didConnect:)连接建立成功iOS 5
centralManager(_:didFailToConnect:error:)连接请求失败iOS 5
centralManager(_:didDisconnectPeripheral:error:)连接断开（error 为 nil 表示主动断开）iOS 5
centralManager(_:willRestoreState:)系统后台恢复 App 时交还保存的状态（配合 iOS 7 的恢复机制，见 C9）iOS 7 机制
centralManager(_:connectionEventDidOccur:for:)注册过的连接/断开/通知事件发生（配合 registerForConnectionEvents）iOS 13

2.2 CBPeripheralDelegate：属性发现与数据事件

回调何时触发引入
peripheral(_:didDiscoverServices:)discoverServices 完成，读 peripheral.servicesiOS 5
peripheral(_:didDiscoverCharacteristicsFor:error:)discoverCharacteristics 完成，读 service.characteristicsiOS 5
peripheral(_:didDiscoverDescriptorsFor:error:)discoverDescriptors 完成iOS 5
peripheral(_:didUpdateValueFor:error:)读到值，或订阅的通知/指示到达（同一个回调两用）iOS 5
peripheral(_:didWriteValueFor:error:)带响应写（.withResponse）的结果iOS 5
peripheral(_:didUpdateNotificationStateFor:error:)setNotifyValue 的订阅/退订确认iOS 5
peripheral(_:didModifyServices:)设备端属性表失效（固件升级/服务变化），要重新 discoveriOS 7
peripheral(_:didReadRSSI:error:)readRSSI 的结果iOS 8
peripheralIsReady(toSendWriteWithoutResponse:)无响应写的缓冲又有空位（配合 iOS 11 的 canSendWriteWithoutResponse，见 C8）配 iOS 11
peripheral(_:didOpen:error:)openL2CAPChannel 的结果，拿到输入/输出流iOS 11
说明willRestoreState 与 peripheralIsReady 的文档页标注为 iOS 5（协议整体引入版本），但它们服务的机制分别自 iOS 7（State Restoration）与 iOS 11（无响应写流控）才可用，工程上按后者对待。
重点 · 与 Android 对照Android 的 BluetoothGattCallback ≈ iOS 的两个 delegate；Android 句柄 ≈ iOS 直接拿 CBCharacteristic 对象（不用记句柄）。Android 一个回调管所有事，iOS 按「管理器事件 / 设备数据」拆成两个协议。
本步收束：delegate 回调驱动；Manager 回调管扫描连接，Peripheral 回调管发现与数据；iOS 直接持对象不记句柄。

第 3 步iPhone 既能当中心也能当外设

iPhone 默认中心+Client；用 CBPeripheralManager 也能当外设+Server（C 选修）。两套角色可交叉，与 Android 一致。

你想做什么角色用哪套类
读温度计、连手环、控制智能灯中心 CentralCBCentralManager + CBPeripheral
让 iPhone 模拟一个 BLE 设备被别的手机连外设 PeripheralCBPeripheralManager + CBMutableService/Characteristic
两台 iPhone 互传数据一台中心 + 一台外设两套同时用（MultipeerConnectivity 也是这套底层）

本板课程主线是中心角色（读传感器、控设备），外设角色只在需要时选修。角色是「这次连接里谁主动」，不是设备类型——同一台 iPhone 下一秒就能换角色。

本步收束：角色可交叉，iPhone 双角色都行；主线学中心。

第 4 步最小骨架：从初始化到读到值

把前面的地图落成代码。下面是一份中心角色的最小骨架（省略错误处理），每一步对应一个 delegate 回调：

// 1. 初始化：queue 传 nil = 回调走主队列；首次会触发蓝牙授权弹窗
let central = CBCentralManager(delegate: self, queue: nil)

// 2. 等状态回调，poweredOn 才扫描（详见 C2）
func centralManagerDidUpdateState(_ c: CBCentralManager) {
  guard c.state == .poweredOn else { return }
  c.scanForPeripherals(withServices: [CBUUID(string: "1809")], options: nil)
}

// 3. 扫到就停、就连（详见 C3/C4）
func centralManager(_ c: CBCentralManager, didDiscover p: CBPeripheral,
                    advertisementData: [String: Any], rssi: NSNumber) {
  c.stopScan()
  p.delegate = self          // 别忘了设 peripheral 的 delegate！
  c.connect(p, options: nil)
}

// 4. 连上后逐层发现（详见 C5）
func centralManager(_ c: CBCentralManager, didConnect p: CBPeripheral) {
  p.discoverServices([CBUUID(string: "1809")])
}
func peripheral(_ p: CBPeripheral, didDiscoverServices error: Error?) {
  guard let s = p.services?.first else { return }
  p.discoverCharacteristics([CBUUID(string: "2A1C")], for: s)
}

// 5. 订阅温度测量特征，数据从 didUpdateValueFor 到达（详见 C6/C7）
func peripheral(_ p: CBPeripheral, didDiscoverCharacteristicsFor s: CBService, error: Error?) {
  guard let ch = s.characteristics?.first else { return }
  p.setNotifyValue(true, for: ch)
}
func peripheral(_ p: CBPeripheral, didUpdateValueFor ch: CBCharacteristic, error: Error?) {
  guard let data = ch.value else { return }
  // data[0] 是单位标志，后 4 字节是 IEEE-11073 FLOAT 温度（见 C11）
}
重点 · 两个高频新手坑① central 与 peripheral 都要强引用：connect 不会替你持有 peripheral，局部变量出了作用域对象就释放，连接悄悄断。② peripheral.delegate 要单独设：只设 central 的 delegate，连上后一个数据回调都收不到。
本步收束：init → 状态 → 扫描 → 连接 → 发现 → 订阅，六步全异步；强引用两个对象、两个 delegate 都要设。
