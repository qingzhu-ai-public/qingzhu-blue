# 从扫不到到收不到 按通信阶段排障

温度页没更新，先找最后一步成功的记录。手机可能一直没收到广播，也可能已收到通知，只是把温度字节按错误的格式解析了。两种问题在界面上看起来一样，能用的证据完全不同。

| 现象 | 先找的证据 | 下一次怎么验证 |
|---|---|---|
| 扫不到设备 | 是否有该设备的原始广播，是否被过滤 | 把设备移到接收端附近，短时间去掉过滤，用另一台已知能扫描的设备交叉检查 |
| 能扫到但连不上 | 广播是否可连接，连接请求和完成状态各是什么 | 确认设备是否被其他客户端占用，重新扫描获取当前地址与广播状态 |
| 已连接但找不到特征 | 本次服务发现完成状态和实际返回的 UUID 列表 | 核对固件版本和服务表，检查服务变更或客户端缓存 |
| 能读但收不到通知 | 特征属性、本地监听是否启用、CCCD 设置结果 | 完成订阅后触发一个新的读数，同时查看外设发送日志和手机接收日志 |
| 写入报权限错误 | 失败的 ATT 操作、错误码与当前链路的安全状态 | 对照特征权限检查是否需要加密、认证或应用授权 |
| 少量数据正常，大数据出错 | 有效 MTU、每片长度、分片序号、接收窗口 | 在单片上限前后各测一次，再验证重复片、缺片和重组超时 |
| 写入响应成功，界面却显示超时 | 外设是否执行，业务回执的命令编号是否匹配 | 读回配置或核对设备日志，确认命令结果后再决定是否重发 |

## 一次测试留下一条时间线

记录手机系统版本、外设固件版本、每一步的时间和结束状态。一次连接用同一个会话编号，一条业务命令用同一个命令编号。重连后用新会话编号，日志里就能看出超时或回调属于哪一次尝试。

两边的应用日志对不上时，可以进一步看主机和控制器之间的 HCI 日志，或使用空口抓包。HCI 日志适合确认主机下发了什么、控制器回了什么。空口抓包适合观察实际发射的广播和连接数据，能看到多少还取决于捕获条件及链路是否加密。需要共享日志时，先处理设备标识及业务数据。

## 在外设和客户端之间交叉验证

用同一台手机换一台已知正常的外设，再用同一台外设换一台已知正常的手机。每次只改一边，并保持固件、距离和操作顺序可比较。如果换手机才能复现，记录机型与系统版本；如果同一台外设在不同手机上都失败，就从两边共有的广播、服务表或固件行为查起。

Android 上可按[抓包、HCI Snoop 与日志诊断](#android/development-guide/hci-log)采集证据，再查 [GATT 错误码与真机故障](#android/development-guide/gatt-errors)。
