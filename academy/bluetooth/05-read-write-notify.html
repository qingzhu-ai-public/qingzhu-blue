读、写、通知：三种操作与「成功」的层次

数据清单摆好了，怎么操作？Read 和 Write 有来有回，Notify 免签收、Indicate 由协议栈签收。这一课最重要的观念是：每种「成功」只确认自己那一层，业务生效要另外验证。

难度：零基础约 12 分钟含交互演练前置：A4

第 1 步五种操作，各有方向

操作方向协议层结果
ReadClient → Server返回值或错误
Write Request（有响应）Client → Server返回写入响应或错误
Write Command（无响应）Client → ServerATT 没有响应
NotifyServer → Client不要求逐条确认
IndicateServer → ClientClient 回确认，收到前不发下一条
本步收束：读写是手机发起、有来有回；通知/指示是设备发起，Notify 免签收、Indicate 要签收。

第 2 步「成功」只确认自己那一层

重点 · 核心观念Write Response 只说明 ATT 层接受了写入，不代表采样间隔已生效。要确认业务生效，约定带命令编号的结果消息，或读回当前配置。Indicate 的确认由手机协议栈自动回复，App 感知不到；App 是否处理了数据是另一层。无响应写连 ATT 确认都没有，别用来发关键命令。

把「传输成功」「命令执行」「业务生效」当三件事分别确认，重连、重试、幂等才有抓手。

本步收束：传输成功 ≠ 命令执行 ≠ 业务生效，三层各验各的。

第 3 步出错时读哪个字节

失败时 Server 回 Error Response：01 + 出错操作码 + 句柄 + 错误码。

温度计 → 手机   01 12 15 00 05
                │  │  │     └ 0x05 需要认证
                │  │  └ 句柄 0x0015
                │  └ 出错操作 Write Request
                └ Error Response
错误码指向
0x02/0x03Read/Write Not Permitted，特征不允许该操作
0x05需要配对认证（安全层）
0x0F需要加密链路（安全层）
0x08应用层拒绝，配对了也没用，走厂商授权
本步收束：0x05/0x0F 是安全层（配对加密可解），0x08 是业务层（要走厂商授权）。
