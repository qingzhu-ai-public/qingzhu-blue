第 1 步连接与断开监听

const d = await device.connect()
d.onDisconnected(()=>{})
// 完整写法：连接 → 发现 → 断开监听（Subscription 要留好）
const d = await device.connect();        // Promise<Device>
const discSub = d.onDisconnected((err, dev) => {
  // err 带断开原因；清订阅/队列，按策略重连
});
await d.discoverAllServicesAndCharacteristics();
// 主动断开：await d.cancelConnection()
// 或 manager.cancelDeviceConnection(id)
ConnectionOptions平台说明
autoConnectAndroid onlytrue = 设备出现即自动连（慢、省电）；false = 直连
requestMTUAndroid连接时顺带协商 MTU；不保证成功
refreshGattAndroid only固件升级后服务缓存不刷新时用
timeout双端毫秒级连接超时；竞态下可能连上即断
收束：connect Promise；onDisconnected 监听。

第 2 步发现与错误码

await d.discoverAllServicesAndCharacteristics()
  • 为什么必须发现：即使你早已知道服务/特征 UUID，GATT 客户端也要先发现把它们缓存进连接会话，否则读写报 ServicesNotDiscovered / CharacteristicNotFound。
  • 发现耗时：服务/特征越多越慢；官方说明每次连接都要做一次（外设服务集极少变化时才可能复用）。
  • 取列表：await d.services()、await d.characteristicsForService(SVC)；特征属性标志 isReadable / isWritableWithResponse / isNotifiable 决定操作合法性。
BleError 错误码含义处理
DeviceDisconnected操作时连接已断清会话，重连新会话
ServicesNotDiscovered没做 discoverAll补 discoverAllServicesAndCharacteristics
CharacteristicNotFoundUUID 不在发现结果里核对 UUID / 重新发现
CharacteristicWriteFailed / ReadFailed属性不允许该操作看 isWritable… / isReadable 标志
重点连接后发现；重连重新发现/订阅。错误码是 plx 的排障地图：先读 errorCode 再决定重试还是修代码。
收束：发现每连接一次；错误码驱动处理分支。

项记住

      
连接device.connect() → Promise<Device>；manager.connectToDevice(id) 同功

      
选项autoConnect/refreshGatt 仅 Android；timeout 双端

      
断开onDisconnected(cb) → Subscription；主动断 cancelConnection

      
发现discoverAllServicesAndCharacteristics 每连接一次

      
错误码ServicesNotDiscovered → 补发现；DeviceDisconnected → 新会话

      
重连旧对象/旧订阅作废；重新发现+订阅
