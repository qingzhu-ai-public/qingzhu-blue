读写与订阅：monitor characteristic

readCharacteristicForService、writeCharacteristicWithResponse/WithoutResponseForService、monitorCharacteristicForService。这一课讲三种操作与 RN 特有的 base64 解码。

平台：React Native/TS约 22 分钟ble-plx 3.x含两场交互演练跨端对照
1读写ForService

3解码base64→小端

第 1 步读写：值走 base64

await d.readCharacteristicForService(svc, chr)
await d.writeCharacteristicWithResponseForService(svc, chr, base64)
// RN 没有原生字节数组过桥：值统一 base64 字符串
import { Buffer } from 'buffer';   // RN 需 buffer polyfill（样例已带）

const c = await d.readCharacteristicForService(SVC, CHR);
const bytes = Buffer.from(c.value, 'base64');  // 解码成字节

// 写 0x01 请求帧：先编码再写
const cmd = Buffer.from([0x01]).toString('base64'); // "AQ=="
await d.writeCharacteristicWithResponseForService(SVC, CHR, cmd);
// WithoutResponse 版：快，丢包无感知
操作返回可靠性适用
readCharacteristicForService 3.xPromise<Characteristic>（value base64）一次快照初值/低频量
writeCharacteristicWithResponseForService 3.xPromise<Characteristic>（等 ATT 应答）失败 reject BleError关键命令（0x01 请求帧）
writeCharacteristicWithoutResponseForService 3.xPromise<Characteristic>（不等应答）丢包无感知高频流数据
收束：值用 base64 传输。

第 2 步monitor 订阅与两级解码

d.monitorCharacteristicForService(svc, chr, (err, c)=>{ /* c.value base64 */ })

monitor 返回 Subscription（不是 Promise）；库内部写 CCCD 开 notify/indicate，sub.remove() 退订。RN 比 Flutter 多一级解码：base64 → 字节 → 小端数值。

const sub = d.monitorCharacteristicForService(SVC, CHR, (err, c) => {
  if (err || !c?.value) return;
  const b = Buffer.from(c.value, 'base64');
  if (b.length < 7 || b[0] !== 0x40) return;   // 防截断/异帧
  const t = b.readInt16LE(2) / 100;            // sint16
  const h = b.readUInt16LE(5) / 100;           // uint16
  setTemp(t); setHum(h);
});
// 退出页面：sub.remove()（F6）
重点RN 值 base64，先解码再小端解析。大端读 C4 09 得 50185（501.85°C）；getUint16 读零下帧得 65036——两级解码每级都有坑。
收束：monitor 收 base64；Buffer 解码 + 小端 + 符号 ×0.01。

项记住

      
读read…ForService → Characteristic.value（base64）

      
关键写write…WithResponseForService(s, c, base64)；0x01 = "AQ=="

      
流式写WithoutResponse（快，丢包无感知）

      
订阅monitor…ForService → Subscription；库代写 CCCD

      
解码Buffer.from(value,'base64') → readInt16LE/readUInt16LE ×0.01

      
防坑先验长度/帧头；大端误读、零下补码、跳过 base64 是三大坑
