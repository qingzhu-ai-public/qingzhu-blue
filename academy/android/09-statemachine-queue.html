线程、状态机与命令队列：每命令只结一次账

取消、断开、超时三个入口同时到，各自清理就会先「已取消」又「失败」。这一课讲把一条连接交给一个串行环境，按钮/回调/超时只投递事件，每命令只完成一次。

平台：Android/Kotlin约 14 分钟含交互演练前置：B5

第 1 步所有入口只投递，不直接改状态

private val worker = Handler(HandlerThread("ble-session").apply{start()}.looper)
fun onUserCancel() { worker.post { handle(Event.Cancel) } }
fun onWriteTimeout(id:Long) { worker.post { handle(Event.Timeout(id)) } }
override fun onCharacteristicWrite(g,c,status) { worker.post { handle(Event.WriteDone(g,c.uuid,status)) } }
本步收束：按钮/定时器/回调都 post 进同一队列，串行处理。

第 2 步CONNECTING→DISCOVERING→CONFIGURING→READY

CONNECTING → DISCOVERING → CONFIGURING → READY
任一状态遇超时/断开/取消 → CLOSING → CLOSED

进 CLOSING 后再来的事件只走清理，不推进状态。发 API 前记录在等什么+设期限。

本步收束：状态机列出在哪步、允许去哪步；关闭后只清理。

第 3 步验代次丢旧回调，每命令完成恰好一次

重点 · 实现清单① 验代次：旧 GATT 迟到事件丢弃；② CLOSING 只清理；③ WriteDone 匹配 GATT 实例+操作类型+特征 UUID 才算终态；④ 成功/同步拒绝/超时/取消四选一完成一次；⑤ 完成取下一条，队列满返回忙。operationId 是 App 标识，平台回调没有，靠三要素匹配。
本步收束：代次隔离旧会话；每命令只结一次账。

动手提交命令后注入取消/超时/断开，看只结一次

点「提交写命令」进入 inflight。再点取消/超时/断开/成功之一，观察命令只完成一次；之后到的旧回调被代次丢弃。
