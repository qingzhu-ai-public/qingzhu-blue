订阅与通知：两步缺一不可

setCharacteristicNotification 只是本地登记，还要向 CCCD 写开启值设备才发。这一课把 Android 两步订阅、CCCD 取值、Notify 与 Indicate、回调线程与重连残留逐一讲清，并给出官方依据。

平台：Android/Kotlin约 22 分钟API 18 → 33含交互演练前置：B5

2CCCD取值

第 1 步本地登记 + 写 CCCD，两步缺一不可

gatt.setCharacteristicNotification(ch, true)          // ① 本地
val cccd = ch.getDescriptor(UUID.fromString("00002902-0000-1000-8000-00805f9b34fb"))
// API 33+ 新签名直接传值
gatt.writeDescriptor(cccd, BluetoothGattDescriptor.ENABLE_NOTIFICATION_VALUE)  // ② 01 00
// 等 onDescriptorWrite 成功，再触发新读数验证
本步收束：setCharacteristicNotification + writeDescriptor(CCCD) 两步；等 onDescriptorWrite 再验证。

第 2 步CCCD 取值与 Notify / Indicate

CCCD 值常量含义
00 00DISABLE_NOTIFICATION_VALUE关闭
01 00ENABLE_NOTIFICATION_VALUENotification（无确认）
02 00ENABLE_INDICATION_VALUEIndication（有确认）
NotificationIndication
确认无，设备发完即走有，客户端自动回 Confirmation
吞吐高，可连续多条低，一条一等
可靠可能丢不丢（链路层确认）
特征 propertyPROPERTY_NOTIFYPROPERTY_INDICATE
重点CCCD（0x2902）是每个可通知特征各一个的描述符。写错值（如该 Indicate 却写 01 00）设备可能不发。Android 对 Indication 的确认由协议栈自动回，App 仍走 onCharacteristicChanged。
本步收束：00 关 / 01 Notify / 02 Indicate；Notify 快可丢、Indicate 慢可靠。

第 3 步onCharacteristicChanged 与回调线程

// API 33+ 新签名：value 直接传入，避免竞态
override fun onCharacteristicChanged(g:BluetoothGatt, ch:BluetoothGattCharacteristic, value:ByteArray) {
  val bytes = value.copyOf()   // 立即复制
  worker.post { decode(bytes) } // 解码放工作线程
}
  • 回调默认在 Binder 线程，不是主线程；别在里面做耗时解码/IO，也别直接更新 UI。
  • 旧签名里 ch.value 会被后续操作复用，立即 copyOf() 再投递。
  • Android 26+ 可在 connectGatt 传 Handler 指定回调线程；更新版本可用 Executor。
本步收束：回调里复制字节、工作线程解码；33+ 用带 value 新签名。

第 4 步绑定重连的 CCCD 残留

绑定（bonded）设备重连后，服务端可能保留旧 CCCD 直接开始发；而本地 setCharacteristicNotification 还没重新登记 → 系统收到却不交给 App，表现为「丢数据」。重连务必重新两步订阅，不要假设上次的订阅还在。

本步收束：重连重新登记本地 + 确认 CCCD，别依赖残留。
