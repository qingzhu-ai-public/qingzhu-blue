按阶段排障：最后成功定位法

排障方法跨平台通用：先找最后一步成功记录钉住阶段，再取证。这一课把通用方法落到鸿蒙：五道关证据链、十个错误码速查、hilog 会话编号归因。

平台：HarmonyOS/ArkTS约 24 分钟错误码速查含两场交互演练跨端对照

第 1 步五道关与证据链

广播→连接→发现→订阅→业务。先问最后成功记录，钉住阶段再取证（同 A10）。

收束：先定位再取证；每关只认自己的证据。

第 2 步错误码速查：号码即阶段

错误码含义钉在哪关第一反应
201权限拒绝⓪ 门控查声明+弹窗授权（D2）
401参数错误任意查 UUID 格式 / ArrayBuffer / 枚举值
801能力不支持任意设备不支持该特性（如扩展广播）
2900001蓝牙服务停止⓪ 门控等系统服务恢复再试
2900003蓝牙未开启⓪ 门控getState 门控 + stateChange（D2）
2900009扫描硬件资源不足① 广播过滤器太多（≤3）/ 别的 App 占着
2900011操作忙③④⑤GATT 串行：等上一步回调（D4）
2900099操作失败任意通用失败：抓 hilog 看底层原因
2901003设备未连接② 连接CONNECTED 回调到了吗？重连了吗？
2902050扫描已开启① 广播单路扫描：先 stopBLEScan 再换过滤
重点错误码本身就是定位信息：2900011 不用猜，就是串行没守住；2902050 就是重复开扫描。把 catch 里的 code 记进日志，排障快一半。
收束：号码即阶段；catch 必记 code。

第 3 步鸿蒙日志与会话编号

记录 BLEConnectionStateChange / getServices 结果 / BLECharacteristicChange 是否进。会话编号归因迟到回调。

import { hilog } from '@kit.PerformanceAnalysisKit';
let session = 0; // 每次 connect 递增

dev.on('BLEConnectionStateChange', (s) => {
  hilog.info(0x0001, 'BLE', 's%{public}d state=%{public}d', session, s.state);
});
dev.on('BLECharacteristicChange', (ch) => {
  hilog.info(0x0001, 'BLE', 's%{public}d ch=%{public}s len=%{public}d',
    session, ch.characteristicUuid, ch.characteristicValue.byteLength);
});
// 迟到回调：s3 的帧在 s4 会话里到达 → 按编号丢弃，别污染新会话
  • 界面不更新≠没收到事件：回调日志与 UI 日志分开记，先分清是④还是⑤的问题。
  • 虚拟 MAC 陷阱：重启蓝牙后 deviceId 变了，旧日志里的地址对不上新扫描——用会话编号+广播内容归因，别用地址。
  • hilog 过滤：DevEco Studio Log 面板按 tag=BLE 过滤；真机 hdc shell hilog 同样可抓。
重点界面不更新≠没收到事件，分开记。
收束：每条日志带会话编号；迟到回调按编号丢弃。
