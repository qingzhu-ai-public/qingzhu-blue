配对与 LE 安全：createBond 与加密事件

写配置返回 0x05/0x0F，是安全层问题。这一课把 createBond 与绑定状态广播、LE 配对方式与密钥、加密重新启用、ATT 安全错误码、恢复出厂两侧清密钥逐一讲清，并给出官方依据。

第 1 步createBond 与绑定状态广播

device.createBond()                 // API 19，异步
// 监听 ACTION_BOND_STATE_CHANGED：
// EXTRA_BOND_STATE: BOND_NONE(10) → BOND_BONDING(11) → BOND_BONDED(12)
// EXTRA_PREVIOUS_BOND_STATE 看从哪来；失败回 BOND_NONE
API / 常量说明级别
createBond()发起配对19
createBond(transport)指定 TRANSPORT_LE / BR_EDR19
getBondState()查当前绑定状态早期
removeBond()删绑定（隐藏 API，反射/系统设置）非公开
本步收束：createBond 异步，监听 BOND_STATE_CHANGED 三态；removeBond 非公开。

第 2 步LE 配对方式与密钥

配对方式交互安全
Just Works无确认无 MITM 保护
Numeric Comparison两端比 6 位数字有 MITM（LE Secure Connections）
Passkey Entry输入 6 位密钥有 MITM
OOB带外（NFC 等）取决于带外通道

密钥：配对生成 LTK（长期密钥，加密用）、IRK（身份解析，解析私有地址）、CSRK（签名）。LE Secure Connections（BT 4.2）用 ECDH，更安全。绑定（bonding）= 配对 + 保存密钥供重连。

本步收束：四种配对方式；LTK 加密 / IRK 解析地址 / CSRK 签名；绑定=配对+存密钥。

第 3 步绑定重连要重新启用加密 + 错误码分层

绑定保存 LTK/IRK，但重连后不自动加密，要用保存的 LTK 重新启用（访问受保护特征时协议栈触发）。分清三层错误：

ATT 错误含义层处理
0x05Insufficient Authentication安全层配对
0x0FInsufficient Encryption安全层启用加密
0x08Insufficient Authorization业务层走厂商授权
本步收束：重连重新启用加密；0x05/0x0F 安全层、0x08 业务层。

第 4 步恢复出厂两侧密钥一起清

重点 · 高频客诉外设恢复出厂丢密钥，手机留旧 LTK → 加密失败「连上但读写报错 / 反复弹配对」。用 removeBond()（反射 / 系统设置）删旧绑定重新配对。把恢复出厂列入测试用例。
本步收束：密钥失效要删旧绑定重配，两侧一起清。
