服务与特征：两级发现的回调链

discoverServices 后 didDiscoverServices，再 discoverCharacteristics 后 didDiscoverCharacteristics。iOS 两级发现都要等回调，拿到的直接是对象。这一课把发现 API 族、CBCharacteristic 的每个字段、properties 全部能力位、服务表缓存与变更逐一讲清。

第 1 步先服务后特征，各等回调

peripheral.discoverServices([CBUUID(string:"1809")])
// didDiscoverServices → 对每个 service:
peripheral.discoverCharacteristics([CBUUID(string:"2A6E")], for: service)
// didDiscoverCharacteristics → 拿 characteristic 对象
API回调作用引入
discoverServices(_:)didDiscoverServices发现服务；传 UUID 数组缩小范围，传 nil 全发现（慢）iOS 5
discoverIncludedServices(_:for:)didDiscoverIncludedServicesFor发现某服务引用的子服务（少见）iOS 5
discoverCharacteristics(_:for:)didDiscoverCharacteristicsFor发现某服务下的特征；同样建议传 UUID 数组iOS 5
discoverDescriptors(for:)didDiscoverDescriptorsFor发现特征的描述符（CCCD 等，通常不用手动碰）iOS 5
重点 · 传 nil 的代价discoverServices(nil) 会枚举设备全部服务与后续全部特征，慢且费电，还可能拿到一堆无关服务。工程上永远传你关心的 UUID 数组；只有调试摸不清设备时才全发现。
本步收束：两级发现各等回调；可传 UUID 缩小范围；顺序不能反。

第 2 步iOS 拿对象，不记句柄：字段与能力位

didDiscoverCharacteristics 给的 CBCharacteristic 直接用于 read/write/setNotify，不用记句柄（对照 Android）。properties 标明 read/write/notify。

2.1 CBCharacteristic 的字段

字段含义
uuidCBUUID：特征类型标识（如 2A6E 温度）
properties能力位掩码：能读？能写？能订阅？（见下表）
value最近一次读到/通知到的 Data；没读过为 nil
isNotifying当前是否已订阅（setNotifyValue 成功后为 true）
descriptors描述符数组（发现后才有）
service所属服务（反向引用）

2.2 CBCharacteristicProperties：全部能力位

能力位含义引入
.broadcast值可放进广播（少见）iOS 5
.read可 readValueiOS 5
.writeWithoutResponse可无响应写（快，不保证送达，见 C8）iOS 5
.write可带响应写（didWriteValueFor 确认）iOS 5
.notify可通知（设备主动推，不确认）iOS 5
.indicate可指示（设备主动推，逐条确认）iOS 5
.authenticatedSignedWrites支持签名写（少见）iOS 5
.extendedProperties有扩展属性描述符iOS 5
.notifyEncryptionRequired订阅通知要求加密链路（触发配对，见 C10）iOS 6
.indicateEncryptionRequired订阅指示要求加密链路iOS 6
// 操作前先查能力位，别对着只读特征 write
if ch.properties.contains(.notify) { p.setNotifyValue(true, for: ch) }
if ch.properties.contains(.write)  { p.writeValue(cmd, for: ch, type: .withResponse) }

// CBUUID：16 位短号自动展开成 128 位蓝牙基础 UUID
let short = CBUUID(string: "1809")
// 等价于 00001809-0000-1000-8000-00805F9B34FB
let custom = CBUUID(string: "FFE0")          // 厂商自定义 16 位
let long128 = CBUUID(string: "6E400001-B5A3-F393-E0A9-E50E24DCCA9E")  // Nordic UART
本步收束：持对象操作；properties 看能力；CBUUID 短号自动展开，自定义 128 位照写。

第 3 步服务表缓存与变更

系统缓存服务表；固件改表后可能陈旧。iOS 用 Service Changed / 重新发现处理；发现结果与预期对不上先怀疑缓存。

  • 系统级缓存：iOS 把发现过的属性表缓存在系统里，重连同一设备时 discover 秒回——但固件升级改了表，缓存可能还是旧的。
  • didModifyServices（iOS 7）：设备声明服务失效时回调，参数是被作废的服务数组；收到后对受影响服务重新 discover，旧 characteristic 对象作废。
  • Service Changed（0x2A05）：GATT 标准特征，设备端表变化时通知中心；配对过的设备系统会自动处理，App 层配合重新发现即可。
  • 工程兜底：发现结果与固件文档对不上 → 先怀疑缓存；调试期可开关一次蓝牙清缓存；产品固件改表要带 Service Changed 或递增版本号。
func peripheral(_ p: CBPeripheral, didModifyServices invalidated: [CBService]) {
  // 旧对象作废，重新发现受影响的服务
  p.discoverServices([CBUUID(string: "1809")])
}
本步收束：缓存陈旧要刷新再核对；didModifyServices 是官方的「表变了」信号。
