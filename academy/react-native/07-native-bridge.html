第 1 步原生模块：方法暴露

// Kotlin: ReactContextBaseJavaModule @ReactMethod
// JS: NativeModules.BleTask.start(args)
// Kotlin 模块
class BleTaskModule(ctx: ReactApplicationContext)
  : ReactContextBaseJavaModule(ctx) {
  override fun getName() = "BleTask"

  @ReactMethod
  fun start(mac: String, promise: Promise) {
    try {
      nativeBleTask.start(mac)      // 已有原生 SDK/任务
      promise.resolve("ok")
    } catch (e: Exception) {
      promise.reject("START_FAIL", e.message)
    }
  }
}
// 注册：Package.createNativeModules 返回该模块

// JS 侧
import { NativeModules } from 'react-native';
await NativeModules.BleTask.start(mac); // Promise 对应原生 Promise
机制形态适用
NativeModules（旧桥） Bridge@ReactMethod + Promise/回调存量工程、简单命令
TurboModules（新架构） New ArchCodegen spec + JSI 同步/异步新工程默认；类型安全、懒加载
事件发射器原生 emit → JS DeviceEventEmitter扫描/通知帧等持续事件
收束：@ReactMethod 暴露方法。

第 2 步事件：回调转 JS 事件

// Kotlin：SDK 回调 → emit
nativeBleTask.onFrame = { bytes ->
  reactContext
    .getJSModule(RCTDeviceEventEmitter::class.java)
    .emit("onBleFrame", Arguments.fromList(bytes.toList()))
}

});

  • 何时自写：厂商私有 SDK、后台前台服务任务、库未覆盖的私有协议；常规 BLE 直接用 ble-plx。
  • 新架构：TurboModule 用 Codegen 从 TS spec 生成原生接口；事件仍走 EventEmitter 或 Codegen 事件发射器。迁移时方法签名以 spec 为准。
  • 线程：旧桥 @ReactMethod 默认在原生模块线程队列；UI 相关操作 post 主线程；SDK 回调线程注意切换。
重点原生回调转 JS 事件，复用原生能力。JS 侧 addListener 的 subscription 与原生侧回调绑定都要成对清理（F6 同纪律）。
收束：命令走模块方法、事件走发射器；新架构换 JSI 不换心智。
