# 多设备调度

## 为什么不能全部同时连

多个 `connectGatt` 同时发起时，手机蓝牙栈和设备端都会被压住：

- 连接更容易超时或假连；
- 设备端可能进入半连接状态；
- GATT 句柄和连接回调更难收口；
- 传输窗口不受控，回包更容易串。

所以建连阶段有串行闸门，一次只发起一个连接；连接建立后可以保留多条连接。

## 三个不同的资源

| 资源 | 含义 | 默认 |
|---|---|---:|
| 连接容量 | 最多同时保留多条连接 | 自动建议 |
| 传输窗口 | 同时允许多少台设备发送 | 1（串行） |
| 单设备 GATT | 同一台设备内部的操作顺序 | 始终串行 |

它们不是同一个旋钮。

## 配置

```java
QingzhuSdk.setMaxConnections(0); // 0 = 自动建议；1-N = 手动
QingzhuSdk.setMaxTransfers(1);   // 1 = 串行传输
QingzhuSdk.setMaxPendingIntents(8);
```

普通机型建议从：

```text
自动连接容量 + 传输窗口 1
```

开始，目标机型验证稳定后再提高传输并发。

## 自动批次学习

自动模式下，普通 `submit` 的任务会被收集成一个学习批次：

```text
任务全部终态
  → 至少 3 台样本
  → 3 秒静默窗口
  → 汇总成功 / 连接失败 / 操作失败 / 取消
  → 回灌并发建议
```

手动设置并发时，批次仍会记录经验，但不会覆盖手动值。

当前保护：

- 少于 3 台样本跳过；
- 取消批次跳过；
- 10 分钟未收口则强制结算，未终态按取消处理；
- 学习结果持久化。

## 效果边界

当前能证明的是任务、意图、批次和终态逻辑有单元测试覆盖；还没有大规模真机矩阵、长期浸泡和不同厂商 ROM 的统计结果。不要把“能自动学习”误解为“所有机型都已调优”。
