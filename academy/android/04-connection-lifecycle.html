连接生命周期：connectGatt、状态码与关闭

connectGatt 拿到句柄不等于连上。这一课把建连的四个重载、BluetoothGattCallback 的全部回调、两套容易混淆的 status 命名空间、disconnect 与 close 的本质区别、连接参数调节，以及「重连必须当新会话」逐一讲清，并给出官方依据。

第 1 步连接全景：状态机与两套 status

一个 GATT 客户端从创建到释放，走这样一条状态链。注意：拿到 BluetoothGatt 对象 ≠ 已连接，真正连上要以 onConnectionStateChange 的 newState=STATE_CONNECTED 为准。

先记住一件事Android 里有两套 status：连接态回调 onConnectionStateChange 的 status 是 HCI 链路码（8/19/22/62/133…）；而读写 / 发现 / MTU 等操作回调的 status 是 GATT 操作码（GATT_SUCCESS=0、GATT_INSUFFICIENT_AUTHENTICATION=5、GATT_FAILURE=257…）。两者数值含义不同，别混着读。第 4 步分开讲。
本步收束：句柄≠连上；状态机由回调驱动；连接态用 HCI 码、操作用 GATT 码，两套分开。

第 2 步connectGatt 家族：四个重载逐一讲

重载多出的参数引入
connectGatt(ctx, autoConnect, cb)基础版18
connectGatt(ctx, autoConnect, cb, transport)transport：TRANSPORT_AUTO / LE / BR_EDR23
connectGatt(ctx, autoConnect, cb, transport, phy)phy：PHY_LE_1M_MASK 等掩码26
connectGatt(ctx, autoConnect, cb, transport, phy, handler)handler：指定回调线程26

val gatt = device.connectGatt(ctx, false, callback,
    BluetoothDevice.TRANSPORT_LE, BluetoothDevice.PHY_LE_1M_MASK, handler)

2.1 autoConnect：直连 vs 机会连

autoConnect行为适用
false立即直连，约 30 秒超时（AOSP 链路超时），失败快用户主动「连接」按钮
true后台机会式：设备进入范围才连，无固定超时，首连慢、省电长期伴随设备（手环 / 价签网关）

2.2 transport 与 phy

双模设备务必显式 TRANSPORT_LE，否则 AUTO 可能走经典蓝牙导致奇怪失败。phy 掩码决定在哪些物理层发起连接（1M / 2M / Coded），与 B7 的 PHY 协商配合。

已知坑带 handler 的六参重载在 API 26（Android 8.0）上有 bug，回调可能丢失，27 才修复。兼容做法：26 上退回五参重载，27+ 再用 handler 版（Nordic BLE Library 即如此处理）。

2.3 权限

Android 12+（31+）建连需要 BLUETOOTH_CONNECT（运行时权限）；11 及以下用 BLUETOOTH。注意：连接不需要位置权限，位置只卡扫描（B3）。

本步收束：直连 false、伴随 true；显式 TRANSPORT_LE；handler 版避开 API 26；12+ 要 BLUETOOTH_CONNECT。

第 3 步BluetoothGattCallback：全部回调逐一讲

回调触发引入
onConnectionStateChange(gatt, status, newState)连上 / 断开，status 为 HCI 码18
onServicesDiscovered(gatt, status)discoverServices 完成18
onCharacteristicRead / Write / Changed读 / 写 / 通知到达18
onDescriptorRead / Write描述符读 / 写（含 CCCD）18
onReadRemoteRssi(gatt, rssi, status)readRemoteRssi 结果18

onServiceChanged(gatt)对端 GATT 库变了，须重新 discoverServices31
onConnectionUpdated(gatt, interval, latency, timeout, status)连接参数更新较新

API 33 签名变更Android 13 起，onCharacteristicRead / onCharacteristicChanged / onDescriptorRead 新增直接带 byte[] value 的重载，旧签名（自己去 characteristic.getValue()）被标记废弃。新代码用带 value 的重载，避免读到被后续操作覆盖的旧值。
本步收束：回调按操作分配；onServiceChanged 要重发现；33 起用带 value 的新签名。

第 4 步两套 status：HCI 链路码 vs GATT 操作码

4.1 连接态：onConnectionStateChange 的 HCI 码

status含义第一步排查
0 (0x00)GATT_SUCCESS，操作成功看 newState 是连上还是断开
8 (0x08)HCI 连接超时距离 / 干扰 / 连接参数 / 设备是否还在广播
19 (0x13)对端主动断开查设备为什么断（固件 / 电量 / 策略）
22 (0x16)本机主动断开查自己 disconnect / 系统回收
62 (0x3E)连接建立失败句柄新鲜度 / 可连接性 / 是否刚扫到就连
133 (0x85)通用内部错误（GATT_ERROR）不能直接怪固件，先定位阶段再找紧邻系统事件

4.2 操作态：读写 / 发现 / MTU 的 GATT 码

常量值含义
GATT_SUCCESS0成功
GATT_INSUFFICIENT_AUTHENTICATION5 (0x05)需要配对 / 认证
GATT_INSUFFICIENT_ENCRYPTION15 (0x0F)需要加密链路
GATT_INVALID_ATTRIBUTE_LENGTH13 (0x0D)写入长度非法（超 MTU-3 等）
GATT_CONNECTION_CONGESTED143 (0x8F)链路拥塞
GATT_FAILURE257 (0x101)通用失败
133 定位法133 是「筐」错误，覆盖建连 / 发现 / 服务变更各阶段。日志要写全来源：op=connect gen=3 cb=onConnectionStateChange status=133 newState=DISCONNECTED elapsed=…，再结合 阶段 + HCI 抓包（B12）+ 紧邻系统事件 三件套定位，而不是甩锅固件。
本步收束：连接态读 HCI 码、操作读 GATT 码；133 需阶段+HCI+对照定位。

第 5 步disconnect ≠ close，重连当新会话

方法做什么之后
disconnect()断链路，触发 onConnectionStateChange→DISCONNECTED，GATT 客户端仍注册对象保留，理论上可 connect() 重连
close()注销客户端，释放连接槽不再有任何回调；对象作废
重点 · 泄漏系统对 GATT 客户端注册数有上限（常见约 6–7 个）。只 disconnect 不 close，槽位不释放，攒满后新连接直接 133 / 62。不用了必须 close；重连推荐 close 旧的、connectGatt 新的。

5.1 重连 = 新代次（generation）

把每次连接编一个代次号。重连时丢弃旧代次的迟到回调（旧连接可能在后台慢悠悠连上又回调，污染新状态），并在新会话里重新走完整流程：

  • 重新 discoverServices()（服务句柄可能变）；
  • 重新订阅 CCCD（通知不会自动恢复，见 B6）；
  • 重新 requestMtu()（MTU 不跨连接保留，见 B7）；
  • 所有回调先校验代次，过期直接忽略。
本步收束：临时断用 disconnect，彻底释放用 close；重连新代次、丢旧回调、重发现重订阅重 MTU。

第 6 步连接参数：priority、MTU、PHY

6.1 requestConnectionPriority（API 21）

档位典型连接间隔（AOSP 映射，厂商可调）适用
CONNECTION_PRIORITY_HIGH≈ 11.25 – 15 ms高速传输 / OTA，短时用，费电
CONNECTION_PRIORITY_BALANCED≈ 30 – 50 ms默认，日常交互
CONNECTION_PRIORITY_LOW_POWER≈ 100 – 125 ms低频伴随，省电

它只是请求，最终由对端与控制器协商；结果可经 onConnectionUpdated 观察。传完大数据记得降回 BALANCED / LOW_POWER。

6.2 MTU 与 PHY（详见 B7）

requestMtu(n)（21）协商 ATT MTU，结果走 onMtuChanged，默认 23；setPreferredPhy / readPhy（26）协商 1M/2M/Coded，结果走 onPhyUpdate / onPhyRead。两者都不跨连接保留，重连要重来。

本步收束：priority 三档按场景切；MTU/PHY 重连要重协商；参数最终由协商决定。
