分包与流控：maximumWriteValueLength

iOS 用 maximumWriteValueLength(for:) 查单次能写多少，长数据自己切片。withoutResponse 连发靠 canSendWriteWithoutResponse + ready 回调流控。

平台：iOS/Swift约 12 分钟含交互演练前置：C6
1长度maximumWrite
2切片业务分包
3流控ready 回调
4动手算片

第 1 步maximumWriteValueLength(for:)

let n = peripheral.maximumWriteValueLength(for: .withResponse)   // ≈ MTU-3
let m = peripheral.maximumWriteValueLength(for: .withoutResponse) // ≈ MTU-3
本步收束：按类型查单次上限，长数据切片。

第 2 步业务分包带编号序号

跨多次写的记录要带消息编号+分片序号+长度，接收端重组要超时+去重（同 A7/B8）。iOS 不替你重组，业务协议自定。

本步收束：分包编号序号，重组超时去重。

第 3 步withoutResponse 的 ready 流控

while canSendWriteWithoutResponse { write(nextChunk, .withoutResponse) }
// peripheralIsReadyToSendWriteWithoutResponse → 继续发
本步收束：canSend 判断+ready 回调续发，防丢。
