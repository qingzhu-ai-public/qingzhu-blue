订阅与通知：两步缺一不可

setCharacteristicNotification 只是本地登记，还要向 CCCD 写开启值设备才发。这一课讲 Android 的两步订阅、onCharacteristicChanged 与回调线程。

平台：Android/Kotlin约 12 分钟含交互演练前置：B5
1本地setNotify
2远端写CCCD
3回调onChanged
4线程复制数据
5动手两步

第 1 步本地登记 + 写 CCCD

gatt.setCharacteristicNotification(ch, true)          // 本地
val cccd = ch.getDescriptor(UUID.fromString("00002902-…"))
cccd.value = BluetoothGattDescriptor.ENABLE_NOTIFICATION_VALUE  // 01 00
gatt.writeDescriptor(cccd)                            // 远端，等 onDescriptorWrite
重点只做本地：设备不发；只写 CCCD：系统不交给 App。两步齐备再触发新读数验证。Indicate 用 ENABLE_INDICATION_VALUE（02 00）。
本步收束：setCharacteristicNotification + writeDescriptor(CCCD) 两步。

第 2 步onCharacteristicChanged 与线程

override fun onCharacteristicChanged(g:BluetoothGatt, ch:BluetoothGattCharacteristic) {
  val bytes = ch.value.copyOf()   // 立即复制，回调线程数据会被复用
  worker.post { decode(bytes) }   // 解码放工作线程
}
注意回调在 Binder 线程，立即复制字节再投递；解码/IO 放工作线程，别堵回调。Android 26+ 可用 Handler 指定回调线程，37+ 用 Executor。
本步收束：回调里复制字节、工作线程解码。

第 3 步绑定重连 CCCD 残留

绑定设备重连后服务端保留旧 CCCD 可能直接发，而本地 setCharacteristicNotification 还没重新登记→丢数据。重连务必重新两步订阅。

本步收束：重连重新登记本地+确认 CCCD。

动手开关两步，看通知流不流

两个开关代表 setCharacteristicNotification（本地）与 writeDescriptor(CCCD)（远端）。点「设备发通知」，只有两步都开 onCharacteristicChanged 才进 App。
