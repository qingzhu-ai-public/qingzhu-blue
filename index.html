青竹 Blue 是一套给开发者的蓝牙开发工具包（BLE SDK）。你只管描述「要什么」——连接、心跳、重连、并发、排队、超时、防撞车，全在底层替你扛。它不是又一层「帮你发个广播」的薄壳，而是一台点火、挂好挡、装好安全气囊的引擎：坐上去，踩油门就行。

Pain Points

「连上、发指令、收回复」，
哪一步都埋着坑

对接一个 BLE 设备，看起来只是「连上、发指令、收回复」。但真要落地，下面这些坑一个都躲不掉——而且只在真机上、设备一多之后才暴露

01

「连上就行」？

多台同时连会撞车报错；设备还会换地址——拿昨天记住的地址去连，必失败。

02

「断了就重连」？

设备硬断电时，系统根本不通知你断了——界面会永远显示「已连接」。

03

「发数据就发」？

同一台设备并发发两条指令，应答会串包、丢失，回来的数据对不上号。

04

「连几台都行」？

不同手机的蓝牙栈能力不同。写死 7 台，差的手机直接崩。

05

「连上就完事」？

连接要串行、收发要并行、超时要兜底——少一样，一台卡住就堵死全部。

这些问题，青竹 Blue 全部吃进了 core——不是给你一堆零件自己拼，而是变成 SDK 的内部策略。你面对的，是 5 个方法。

The API

五个方法，
覆盖全部场景

scan / find / connect / config / sendMessage 五个基础方法，外加 findAndConnect、findAndConfig 两个组合形态。没有一个方法是「内部细节」——你不需要知道连接池，不需要管 worker，不需要写重连逻辑

01

scan｜扫一圈，全看见

就像开收音机扫台——转到哪儿听到哪儿，周边有什么设备全报上来

开发者用它做「设备发现页」：周边的 BLE 设备实时列出来，点哪个连哪个
无目标扫描扫到即回调零配置可用
02

find｜出现即动手

就像在车站出口举牌接人——人一出现就认出来，不用挨个去问

开发者用它做「目标设备查找」：地址未知或会变（随机化 MAC），SDK 盯着广播，一出现就回调
地址未知 / 会变自动开扫找到即回调
03

findAndConnect｜找到就不撒手

就像接到人之后一路跟着走——人在哪儿你在哪儿，走散了马上追上去

开发者用它做「设备管理页」：找到即连、长连接保持，随时下命令
长连接保持心跳探活掉线自动重连
04

findAndConfig｜配完就走

就像流动疫苗接种——找到一位、打一针、下一位，队伍走到哪儿打到哪儿

开发者用它做「批量配置」：一批设备逐个连上、配好、自动断开，跑一半还能加任务
任务池异步运行期加任务结果汇总
05

connect / config｜设备已知，直接干

就像电话簿里已经存了号——想长聊（connect）还是说一句就挂（config），随你

开发者用它做「直连场景」：扫码或列表选中的设备直接连；改参数用 config，配完自动断
长连接或一次性主动断开不误重连中途取消
06

sendMessage｜一问一答，必有结果

就像发消息等回复——要么等到，要么超时，绝不让你干等着

开发者用它做「指令收发」：发一条指令拿一个应答，多台并发也不串包
按 MAC 串行订阅应答分离超时兜底

差别一句话说清：地址未知 / 会变 → find* 系列（SDK 盯着广播，一出现就动手）；设备已在手 → connect / config（直接干）；只配一下就走 → config / findAndConfig（配完自动断）；要长期保持 → connect / findAndConnect（一直在线）

Inside the SDK

外面几行，
里面是这些

五个方法背后，是同一批硬骨头。SDK 的追求：把复杂全包在里面，你只说「我要连哪几台」「我要发什么」

长连接
心跳探活（硬断电也判得出）掉线自动重连重试·间隔·退避可配主动断开不误重连
智能多连接
并发容量自学习建连串行·收发并行新鲜地址闸门不写死台数
任务池
一切皆异步任务运行期随时加任务中途取消逐台回调·整批汇总
收发管道
按 MAC 串行不串包订阅与应答分离每一步超时兜底心跳指令同队列
传输加速
连接即提优先级写类型可配大块传输保活吞吐明显提升

以上是 SDK 的设计范围与目标（Android 先行实现，其余平台按同一套结构铺开）；实际进度以 GitHub 仓库为准。

Zero Config · Pluggable

零配置能用，
想定制全有口子

core 是引擎，你的设备协议是插件。先保证「什么设备都能连」，再谈定制——要改的地方都有干净的口子，没有「改 core 源码」这条路

✓

零配置开箱即用

什么都不配直接可用：默认就是标准 connectGatt + 自动发现服务，不配任何 UUID、PHY、MTU，就能扫所有设备、连任意设备、浏览服务——开箱即用，等价于你熟悉的 nRF Connect。

⚙

一切皆可配置

ble.settings() 一个入口调所有：重连几次、写类型、心跳间隔……每项带 key / 类型 / 默认值 / 中文说明。不配 = 用默认值；配错了开发期直接报错并列出可用 key，绝不静默失效。

✚

协议是插件

对接一台新设备，核心只问你要 4 样东西（广播识别、编解码；心跳、认证全可选）——通常只新增 5 个小类，不改 core 一行代码；覆盖不到，还有 connectSteps() 逃生舱。

↗

白标只要几分钟

core 用 implementation 依赖，你只做薄门面 + 类型适配，就能出「自己公司命名」的 SDK（如 XBle）；core 升级，你的 SDK 白得新能力。
