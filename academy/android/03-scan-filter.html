扫描与过滤：ScanFilter 与限流

startScan 把附近广播全收进来，费电又吵。ScanFilter 让系统只把匹配的交给你。这一课讲过滤怎么建、为什么加了过滤设备消失，以及 Android 的扫描限流。

平台：Android/Kotlin约 12 分钟含交互演练前置：B2

2过滤ScanFilter

第 1 步startScan + ScanCallback

val cb = object : ScanCallback() {
  override fun onScanResult(type:Int, r:ScanResult) {
    val dev = r.device; val rssi = r.rssi
    val record = r.scanRecord   // 原始广播字节
  }
  override fun onScanFailed(code:Int) { /* 1 重复注册 2 注册失败 6 过频 */ }
}
scanner.startScan(filters, settings, cb)
本步收束：每个广播回调一次 onScanResult；onScanFailed 的 1/2/6 各有含义。

第 2 步过滤条件必须真的在广播里

val f = ScanFilter.Builder()
  .setServiceUuid(ParcelUuid.fromString("00001809-0000-1000-8000-00805F9B34FB"))
  .build()
重点 · 高频坑服务 UUID 过滤失效，多半是 UUID 根本没写进广播（设备连接后才暴露服务）。名字过滤失效可能是名字在扫描响应里平台没交付。RSSI 过滤慎用（波动大）。排查先去掉全部过滤看原始字节。
本步收束：过滤字段必须真实存在于广播；筛不到先去掉过滤看 RAW。

第 3 步7.0 限流、8.1 熄屏、后台 PendingIntent

  • Android 7.0 起 30 秒内启停扫描超 5 次被限流（onScanFailed 2/6）。
  • 8.1 起熄屏时不带过滤器的扫描暂停——后台扫描务必带 ScanFilter。
  • 进程未运行也要收匹配：用 startScan(filters, settings, PendingIntent)。
本步收束：别频繁启停；后台带过滤；离线匹配用 PendingIntent。

动手勾选过滤条件，看目标设备还匹配吗

看懂这场演练过滤是「与」逻辑：每个条件都必须在广播里真实存在。勾了广播没有的字段（如厂商数据），设备就被滤掉。这正是「加了过滤设备消失」的根因。
