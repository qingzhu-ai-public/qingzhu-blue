综合实战：BTHome 温湿度计 完整 App

与 Android B14、iOS C11 同一个项目：BTHome v2 温湿度计。鸿蒙是三端里角色最全的——既能当接收器，又能当真正的 BTHome 广播源（serviceData），还能当教学 GATT 从端。配套 ArkTS 源码工程 examples/harmonyos/bthome-mvp，教学 UUID 三端一致，可跨平台互连。

平台：HarmonyOS/ArkTS约 45 分钟API 10 → 22配套源码含两场交互演练三端互通
1协议BTHome v2
2解析器对象表+自检
3接收扫描解码
4广播源serviceData
5GATT模拟+连接
6验收三端互通

第 1 步BTHome 是什么、三端同一个项目

BTHome 是开源的 BLE 传感器广播格式（bthome.io）：设备把温湿度等读数塞进广播的服务数据段，任何接收器不用连接就能读。Home Assistant 原生支持，市售大量传感器用它。

平台工程能当什么角色
Android（B14）examples/android/bthome-mvp（Java）接收器 + BTHome 广播源 + 教学 GATT 从端
iOS（C11）examples/ios/bthome-mvp（Swift）接收器 + 教学 GATT 从端（发不出服务数据广播）
鸿蒙（本课）examples/harmonyos/bthome-mvp（ArkTS）接收器 + BTHome 广播源 + 教学 GATT 从端，角色最全
配套源码 · 可以直接编译本课的每一行代码都在 qingzhu-blue / examples / harmonyos / bthome-mvp：协议层（对象表/解析/编码/13 项自检）、扫描接收、广播源、模拟外设、连接客户端全在里面。浏览器里也能先走 交互原型。教学 UUID 与 Android/iOS 完全一致，鸿蒙、Android、iPhone 可以互连。
收束：一个协议、三端实现、同一套教学 UUID；鸿蒙角色最全。

第 2 步从广播包到 BTHome 数据：三层剥开

原始广播 data（ArrayBuffer）
└─ AD 段循环：[len][type][value...]
   └─ type=0x16 且 UUID=FCD2（小端 D2 FC）
      └─ BTHome 载荷：[设备信息1B][对象ID][数据]...
对象 ID含义类型分辨率
0x00序号（packet id）uint81
0x01电量uint81 %
0x02温度sint160.01 °C
0x03湿度uint160.01 %
0x0C电压uint160.001 V
  • 设备信息字节：bit0 加密、bit2 触发式、bit5–7 版本。0x40 = v2 不加密定时。
  • 对象 ID 必须升序；遇到未知 ID 立即停止解析（规范强制）。
  • 官方样例：40 02 C4 09 03 BF 13 → 25.00 °C / 50.55 %；40 02 DA FD → −5.50 °C。
  • 完整对象表几十种（压力/光照/CO₂/门窗…），本课实现常用 5 种，扩展只加表项。
收束：三层剥开：AD 段 → 0x16/FCD2 → 设备信息+升序对象。

第 3 步工程结构：一个 App 四个角色

examples/harmonyos/bthome-mvp/entry/src/main/ets/
├─ bluetooth/
│  ├─ BthomeProtocol.ets    // 对象表 / parse / encode / AD 提取 / 教学协议 / 13 项自检
│  ├─ BthomeScanner.ets     // 接收器：过滤 FCD2 → 解码 → 按 deviceId 合并
│  ├─ BthomeAdvertiser.ets  // 广播源：serviceData 发 BTHome 帧
│  ├─ SensorPeripheral.ets  // 教学 GATT 从端：写 01 回帧
│  └─ SensorClient.ets      // 教学 GATT 中心：连接→写01→读帧→解码
└─ pages/Index.ets          // ArkUI：四个角色页 + 自检面板
  • 协议层零依赖：BthomeProtocol 只碰 Uint8Array/DataView，不碰蓝牙 API——可以离线跑 13 项自检。
  • ArkTS 约束：不用 any/unknown 隐式类型；字节缓冲一律 ArrayBuffer/Uint8Array；回调显式标类型。
  • 权限：module.json5 声明 ACCESS_BLUETOOTH（D2），四个角色共用。
  • 合入方式与 thermometer-mvp 相同：DevEco 新建 Empty Ability，把 ets 目录合进去（README 有步骤）。
收束：协议层与角色层分离；先离线测协议，再上真机。

第 4 步先写解析器，再用官方样例测

// BthomeProtocol.ets（节选）
export function parseBthome(payload: Uint8Array): BthomeReading {
  const info = payload[0];
  if ((info & 0x01) !== 0) { throw new Error('加密帧需要密钥'); }
  const reading: BthomeReading = { version: (info >> 5) & 7, objects: [] };
  let i = 1; let last = -1;
  while (i < payload.length) {
    const id = payload[i];
    if (id < last) { throw new Error('对象 ID 未升序'); }
    const spec = OBJECT_TABLE[id];
    if (!spec) { throw new Error('未知对象 ID 0x' + id.toString(16)); }
    // 小端拼值 → 符号扩展 → 乘分辨率；湿度越界(0–100)报错
    ...
    last = id; i += 1 + spec.len;
  }
  return reading;
}
// 版本兜底：API 10–21 没有 serviceDataMap，手解 AD（D3）
export function extractServiceData(raw: ArrayBuffer, uuid16: number): Uint8Array | null {
  const bytes = new Uint8Array(raw);
  let i = 0;
  while (i < bytes.length) {
    const len = bytes[i];
    if (len === 0) { break; }
    if (bytes[i + 1] === 0x16 && len >= 3 &&
        (bytes[i + 2] | (bytes[i + 3] << 8)) === uuid16) {
      return bytes.slice(i + 4, i + 1 + len);
    }
    i += len + 1;
  }
  return null;
}

13 项自检（源码 selfTest()，App 里一键跑）：官方样例 25.00/50.55、零下 −5.50、电量/电压/序号、升序违规、未知 ID 即停、截断帧、加密帧拒绝、湿度越界、编码→解码闭环、AD 提取命中/未命中。

重点解析器对坏帧要「停下来说清楚」：抛带原因的错误，UI 显示故障而不是硬显示数字。这与 Android BthomeDecoder、iOS BthomeProtocol 的行为一致。
收束：协议层先行 + 官方样例自检；AD 提取兜底旧版本。

第 5 步接收器：只收 FCD2，解码上屏

// BthomeScanner.ets（节选）
ble.on('BLEDeviceFind', (results: Array<ble.ScanResult>) => {
  results.forEach((r: ble.ScanResult) => {
    const payload = extractServiceData(r.data, 0xFCD2);
    if (!payload) { return; }
    try {
      const reading = parseBthome(payload);
      // 按 deviceId 合并（会话内去重；虚拟 MAC 别持久化，D3）
      this.merge(r.deviceId, r.rssi, reading);
    } catch (e) {
      // 坏帧：记日志，不上屏
    }
  });
});
ble.startBLEScan([{ serviceUuid: '0000fcd2-0000-1000-8000-00805f9b34fb' }]);
  • API 22+ 捷径：可直接读 ScanResult.serviceDataMap（系统解析好）；本工程用手解 AD，API 10 起全版本可跑。
  • 过滤：serviceUuid FCD2 对准广播 0x03 段；漏收先去掉过滤看 RAW（D3/D8）。
  • 去重：deviceId 会话内合并；跨会话认设备靠序号对象（0x00）或广播内容。
  • 单路扫描：进连接流程前先 stopBLEScan（D4）。
收束：过滤 FCD2 → AD 提取 → 对象表解码 → 合并上屏。

第 6 步广播源：鸿蒙能发真的 BTHome

// BthomeAdvertiser.ets（节选）
const frame = encodeBthome(25.0, 50.55);  // 40 02 C4 09 03 BF 13
ble.startAdvertising(
  { interval: 1600, txPower: -7, connectable: false },
  {
    serviceUuids: [BTHOME_UUID],
    serviceData: [{ serviceUuid: BTHOME_UUID, serviceValue: frame.buffer }]
  }
);
// 更新读数：stopAdvertising → 改 frame → startAdvertising
平台BTHome 广播源依据
鸿蒙能AdvertiseData.serviceData（API 10）
Android能AdvertiseData.setServiceData
iOS不能startAdvertising 仅 LocalName+ServiceUUIDs 两键
  • 预算：Flags 3 + UUID 列表 4 + 服务数据 11 = 18 字节 < 31（D7 计算器）。
  • connectable=false：纯传感器不需要连接，省电防误连。
  • interval：默认 1600 slot=1s；演示可放宽到 3200（2s）。
  • 验收：A 机发，B 机（鸿蒙/Android/iPhone）收，三端显示同一读数。
收束：serviceData 一填，鸿蒙就是真 BTHome 设备；这是 iOS 做不到的。

第 7 步没有真传感器？三种假数据源

假数据源走什么链路练什么
① 鸿蒙广播源（本课第 6 步）真实射频：BTHome 服务数据广播扫描/过滤/AD 解析全链路
② 教学 GATT 从端（SensorPeripheral）真实射频：连接+写01+读帧连接/发现/读写/串行
③ 协议自检（selfTest）离线：不碰蓝牙对象表/边界/坏帧处理

Android bthome-mvp 也能当①②的信号源；iPhone 只能当②（教学 GATT 从端）和接收器。三种源覆盖 D3–D7 全部技能点。

收束：两台手机就能走完全部链路；一台手机也能离线测协议。

第 8 步教学 GATT 路线：写 01 读帧（三端互连）

// SensorClient.ets（节选）：串行 Promise 链
const client = ble.createGattClientDevice(deviceId);
client.on('BLEConnectionStateChange', async (s: ble.BLEConnectionChangeState) => {
  if (s.state !== constant.ProfileConnectionState.STATE_CONNECTED) { return; }
  const services = await client.getServices();
  const target = findDemoCharacteristic(services);   // …-0602
  // 写 0x01 → 读帧 → parseBthome
});
client.connect();

// 请求读数（等上一步回调再发下一步，D4 串行规则）
const cmd: ble.BLECharacteristic = { serviceUuid: DEMO_SERVICE,
  characteristicUuid: DEMO_CHAR, characteristicValue: new Uint8Array([0x01]).buffer,
  descriptors: [] };
await client.writeCharacteristicValue(cmd, ble.GattWriteType.WRITE);
const resp = await client.readCharacteristicValue(target);
const reading = parseBthome(new Uint8Array(resp.characteristicValue));
教学协议值（三端一致）
服务 UUID476CDF45-6063-43A1-B8E2-8C1FBED00601
特征 UUID（READ+WRITE）476CDF45-6063-43A1-B8E2-8C1FBED00602
指令0x01（请求一帧）
响应帧40 02 <temp sint16 LE> 03 BF 13（湿度固定 50.55%）

从端 SensorPeripheral 用 ble.createGattServer() 建服务，on('characteristicWrite') 收 01 换温度，on('characteristicRead') 用 sendResponse 回帧——与 Android/iOS 的模拟外设行为一致。

收束：同一套 UUID/指令/帧，鸿蒙从端可被 Android/iPhone 连接，反之亦然。

第 9 步验收清单：三端对时间线

#场景通过标准
1协议自检13 项全绿（离线，单机）
2鸿蒙发 → 鸿蒙收B 机列表出现 A 机，读数与 A 机滑杆一致
3鸿蒙发 → Android/iPhone 收三端同一帧解出同一读数
4Android 发 → 鸿蒙收AD 提取兜底路径正确
5鸿蒙从端 → iPhone 连接写 01 读帧成功，温度交替 25.00/26.50
6坏帧越界湿度/未知 ID 显示故障原因，不硬显示
7关蓝牙/撤销权限stateChange 清理，恢复后可重扫（D2）
8断线重连新会话重新发现，迟到回调按会话编号丢弃（D8）
重点对时间线：两端日志都带会话编号与时间戳，「A 机发了、B 机没收到」时先钉阶段（D8 五道关），再查过滤/权限/距离。
收束：8 项验收覆盖协议、射频、跨端、故障四条线。

第 10 步做完之后往哪走

  • 更多对象：照 bthome.io 对象表加压力/光照/CO₂，解析器只加表项。
  • 加密帧：BTHome v2 AES-CCM 加密（bit0=1），需要绑定密钥——进阶课题。
  • 触发式设备：bit2=1 的帧只在事件时发（门窗/按键），配合序号去重。
  • Home Assistant：鸿蒙广播源可被 HA 的 BTHome 集成直接发现——真智能家居入口。
  • 持久标识：虚拟 MAC 会变（D3），跨会话认设备用 access 的持久化设备地址能力或广播序号。
  • 后台：长时任务（continuousTask）保活扫描/广播，按系统功耗策略收敛。
收束：协议是开放表，工程是分层架；扩展不动骨架。
