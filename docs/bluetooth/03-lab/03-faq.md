# 新手 FAQ

收集新手最常问的问题，每个答案先给结论，再给去处。问题按学习顺序排，读正文卡住时来这里对一下。

## 版本与兼容

**蓝牙 5.0 的手机能连 4.2 的传感器吗？**
能。BLE 向后兼容，连接按双方共同支持的能力运行。版本号不承诺具体特性，接设备问能力清单：PHY、MTU、DLE、广播类型、配对方式。详见[版本与能力演进](#bluetooth/fundamentals/versions)。

**经典蓝牙和 BLE 能同时用吗？**
双模手机两套都支持，可以同时连着经典蓝牙耳机和 BLE 传感器。但单模 BLE 设备不能被只支持经典蓝牙的老设备发现，两套无线电物理层不兼容。

**设备标 5.0，为什么没有 2M PHY？**
2M PHY 是可选特性，版本号只是认证标签。SIG 自己都建议按特性描述产品而不是按版本号。

**Bluetooth Mesh 是什么？做传感器要学吗？**
Mesh 是 2017 年单独发布的组网规范，架在 BLE 广播之上，面向几百个节点的灯控和楼宇网络，和 Core 版本号是两套认证。做「一台传感器连手机」用不到它；接组网需求再读 Mesh 规范。见[版本与能力演进](#bluetooth/fundamentals/versions)。

## 扫描与连接

**为什么扫不到我的设备？**
按概率排：设备被另一台手机连着（外设通常只接受一个连接，被连走就停止广播）；过滤条件失配（名字在扫描响应里、UUID 没写进广播、地址轮换了）；广播间隔和扫描窗口没对上。先去掉全部过滤、设备挪近、用 nRF Connect 交叉验证。详见[排障](#bluetooth/communication/troubleshooting)。

**Android 扫描为什么要位置权限？**
历史原因：扫描结果可用于推断位置，Android 6–11 把 BLE 扫描归入位置权限。Android 12 起引入独立的「附近的设备」权限，声明 neverForLocation 后不再要位置。各版本的具体声明见 [Android 权限篇](#android/development-guide/permissions)。iOS 则是蓝牙使用描述，弹的是蓝牙授权。

**一台手机能同时连几台 BLE 设备？**
规范不设上限，实际受手机芯片和系统限制，常见量级是几台到十几台，各厂商不同。连接数越多，每个连接分到的调度越少，吞吐和延迟都会受影响。多设备调度是专门的工程题，Android 侧见[多设备调度](#android/development-guide/thread-state-machine)。

**连接距离有多远？**
1M PHY 室内典型十几米到几十米，受墙体和干扰影响大；Coded PHY 可以到几百米量级但速率大降。别信规格书的「最大距离」，拿目标环境实测。

## 地址与识别

**为什么设备的 MAC 地址过一会儿就变了？**
它用的是可解析私有地址（RPA），定期轮换防追踪，这是隐私设计不是故障。绑定后系统用 IRK 解析身份。业务要长期认设备，用产品自己的稳定标识，别存地址字面值。详见[配对与隐私](#bluetooth/communication/security)。

**iOS 上为什么拿不到 MAC 地址？**
Apple 不给。Core Bluetooth 给的是系统生成的 per-device 标识，同一台外设在两台 iPhone 上标识不同。跨手机关联设备要靠读设备序列号等业务标识。

## 数据与订阅

**要不要配对才能收发数据？**
看设备的特征权限。公开读数的特征不需要配对；要求加密或认证的特征会在读写时报安全错误（如 ATT 0x05/0x0F），这时才走配对。别默认「先配对再干活」，很多设备根本不需要。

**系统设置里配对了，App 里为什么还是连不上？**
系统配对和应用连接是两回事。配对只建立密钥，App 仍要自己扫描、连接、发现服务。而且系统设置页通常只列经典蓝牙和系统级设备，BLE 外设本来就多在 App 内连接。

**订阅成功了为什么收不到数据？**
订阅是两件事：本地登记接收 + 向设备 CCCD 写开启值，缺一件都收不到。都做了就让设备产生一条新读数验证，再看是设备没发还是手机没解析。详见 [GATT 与 ATT](#bluetooth/communication/gatt-att)。

**为什么实际吞吐远低于标称速率？**
PHY 速率是符号速率，应用吞吐还要扣协议头、连接事件调度、MTU 和 DLE 配置、两端处理速度。默认 MTU 23 时每次通知只有 20 字节值，先把 MTU、DLE、连接间隔核对一遍再实测。详见 [MTU 与分包](#bluetooth/communication/data-transfer)。

**温度读出来是六万多度，怎么回事？**
两个经典解析错误：字节序反了（BLE 数值默认小端），或把有符号数当无符号数（零下温度是补码）。24.10 °C 的正确字节是 `6A 09`，-5.50 °C 是 `DA FD`。详见[UUID 与标准服务](#bluetooth/communication/uuid-services)。

## 后台与工程

**App 退到后台还能收数据吗？**
各平台策略不同且都偏严格：iOS 要声明蓝牙后台模式且行为受限，Android 要前台服务保活，HarmonyOS 有自己的长时任务约束。后台是工程深水区，先看对应平台章节（[Android 后台](#android/development-guide/background-service) · [iOS 后台](#ios/development-guide/background)）。

**断线重连后要不要重新订阅？**
要确认，别假设。绑定设备的 CCCD 可能在服务端保留，设备重连后直接开发，而手机本地监听还没登记，数据就丢了。重连当新会话处理：重新登记、确认订阅、核对未完成命令。详见[建连与断线恢复](#bluetooth/fundamentals/connection)。

**网页能直接连蓝牙设备吗？**
能，用 Web Bluetooth，但限 Chrome/Edge 系浏览器，页面要 HTTPS，设备由用户在弹窗里挑选；iOS 上所有浏览器都不支持。做网页配置工具合适，做常驻采集不行。各端能力边界见[平台接口地图](#bluetooth/lab/platform-map)。

**没有硬件能学吗？**
能。一部手机装 nRF Connect 就能做完整链路实验，两部 Android 手机就能双机互测。先做[无代码实验](#bluetooth/lab/nrf-connect-lab)，再进平台课程用模拟器外设或双机方案写代码。

## 一句话总结

**新手疑问大半来自三个混淆：版本号和能力、系统配对和应用连接、协议成功和业务生效；分清这三对概念，问题就少了一半。**
