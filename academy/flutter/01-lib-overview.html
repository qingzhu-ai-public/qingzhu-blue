Flutter 蓝牙全景：flutter_reactive_ble 选型

Flutter 用跨端库屏蔽平台差异。flutter_reactive_ble 提供响应式流 API。这一课讲选型与对象模型，对照原生，并建立「Stream 订阅必须成对清理」的工程直觉。

第 1 步库选型

flutter_reactive_ble（响应式、维护活跃）vs flutter_blue_plus（功能全）。传感器读写订阅两者皆可；本板用 reactive_ble。

候选库API 风格多设备平台适合
flutter_reactive_ble 5.6.0全 Stream（扫描/连接/订阅）原生支持，connectedDeviceStream 汇总Android + iOS本板：流式 UI、多外设
flutter_blue_plus回调 + Stream 混合支持Android + iOS习惯命令式写法的团队
自写 MethodChannel自定义自己实现双端原生各写一遍仅当库无法满足的私有协议（E7）
  • 维护方：pub.dev publisher 为 meethue.com（Philips Hue 团队），BSD-3-Clause；配套样例工程 examples/flutter/thermometer-mvp 锁定 5.6.0，与本课一致。
  • 选型判据：看「结果以什么形态回来」。reactive_ble 把一切结果做成 Stream，UI 用 StreamBuilder 或 listen 消费；代价是必须管理订阅生命周期（第 2 步末）。
收束：按维护/ API 风格选型。

第 2 步流 API：对象模型与逐 API 讲解

final ble = FlutterReactiveBle();
ble.scanForDevices(withServices: []).listen((d){})

// 完整链路（flutter_reactive_ble 5.6.0，签名对照官方类文档）
// 注意：连接方法叫 connectToDevice，不是 connect
final ble = FlutterReactiveBle();
await ble.initialize();
ble.statusStream.listen((s) => print(s)); // 等 BleStatus.ready（E2）

final scanSub = ble.scanForDevices(
  withServices: [Uuid.parse('476cdf45-6063-43a1-b8e2-8c1fbed00601')],
).listen((d) => print('${d.id} ${d.name} ${d.rssi}'));

final connSub = ble.connectToDevice(id: deviceId)
  .listen((u) => print(u.connectionState));

final ch = QualifiedCharacteristic(
  characteristicId: Uuid.parse('476cdf45-6063-43a1-b8e2-8c1fbed00602'),
  serviceId:        Uuid.parse('476cdf45-6063-43a1-b8e2-8c1fbed00601'),
  deviceId: deviceId);
final notifySub = ble.subscribeToCharacteristic(ch)
  .listen((bytes) => print(bytes)); // List<int> 原始字节
API / 对象职责参数与结果来源版本 / 平台
FlutterReactiveBle() / initialize()门面实例与平台栈初始化工厂单例；initialize 完成前操作会失败5.x 双端
statusStream / status蓝牙子系统状态流 / 当前值BleStatus 六态（E2 逐态讲）5.x 双端
scanForDevices(withServices:…)扫描流服务 UUID 列表（官方建议总是指定）；Stream<DiscoveredDevice>5.x 双端
connectToDevice(id:…)连接流Stream<ConnectionStateUpdate>；id 在 Android 是 MAC、iOS 是 UUID5.x 双端
discoverServices(deviceId)服务发现Future<List<DiscoveredService>>；连接后调用（E4）5.x 双端
readCharacteristic(ch)读一次Future<List<int>> 原始字节5.x 双端
writeCharacteristicWithResponse(ch, value:…)带应答写Future<void>；WithoutResponse 版不等应答（E5）5.x 双端
subscribeToCharacteristic(ch)订阅 notify/indicateStream<List<int>>；库内部写 CCCD5.x 双端
requestMtu(deviceId:…, mtu:…)协商 MTUFuture<int> 实际值；iOS 不能协商但可查询当前值5.x Android 协商 / iOS 只读
QualifiedCharacteristic / Uuid.parse三元定位（deviceId+serviceId+characteristicId）Uuid 支持 16/32/128 位；expanded 扩成 128 位5.x 双端
对照原生回调 ≈ Dart Stream；订阅即 listen。Android 侧底层走 RxAndroidBle、iOS 侧走 CoreBluetooth，插件用平台通道把两端统一成同一套 Dart 流。
流listen 得到cancel 的语义
scanForDevicesDiscoveredDevice 事件停止扫描
connectToDeviceConnectionStateUpdate（connecting/connected/disconnected）主动断开该连接
subscribeToCharacteristicList<int> 通知字节退订（库写回 CCCD）
收束：三元定位 + 全 Stream；每个 API 的结果形态（Stream / Future / 字节）决定 UI 怎么接，cancel 不只是停刷新而是真停扫/断连/退订。
